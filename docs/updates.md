# 检查更新与自动发布

## 使用者如何更新

首次使用更新功能需要手动安装一次带“检查更新”的新版。原来的 1.0.0 没有这个入口，无法自行下载第一次升级。

正式安装包从 [GitHub Releases](https://github.com/yxsimony-dot/CCB-USB-User/releases) 下载，选择最新正式版本的 `UsbWebLauncher-<版本>-win-x64-setup.exe`。发布与匿名下载验证结果见 [更新验证记录](update-validation.md)。

应用启动后会在后台检查一次；也可通过维护菜单的“检查更新”查看当前版本、可用版本和更新说明。后台检查不会自动下载安装，不会替你启动银行业务。没有网络时仍可继续使用当前版本，稍后再检查。

修复版优先直接读取正式发布的版本清单和校验文件，正常检查不依赖 GitHub 匿名 API 额度。成功检查结果在当前进程内缓存 60 秒，启动与手动检查共用；刚发布新版时，等待缓存过期后再检查。清单直链返回 404 时才尝试兼容旧 API 查询。其他网络错误、限流或清单异常不会通过不断请求 API 重试。

如果旧版一直显示“GitHub 请求受限”，请先从上面的 Releases 页面手动下载修复版安装包并覆盖安装一次；旧客户端无法通过服务端发布自动改变它自身的查询方式。

找到新版后选择下载，等待进度完成及文件校验通过，再选择安装。如果已经启动了网银业务，请先点击“中止业务”，等页面退出回到空闲状态。下载可以在业务期间进行，安装不能与登录、导出或中止操作同时进行。

安装使用完整安装包：应用正常退出后，按安装向导完成升级，需要时使用同一 Windows 用户确认管理员权限。安装器启动成功不代表升级已经完成。完成后从开始菜单打开应用，确认标题栏版本号；PIN、下载目录和已有 PDF 沿用原设置。

如果取消安装，可以重新打开原应用再试；如果提示上次安装未完成，按 [安装与升级](installation.md) 的恢复步骤处理，保留事务备份。首次安装可在向导中选择目录，后续更新沿用已登记的安装目录。开发目录本身不作为已安装目录，实际目标以安装向导为准。

## 下载失败与异常

- **暂无发布版本**：仓库还没有可用的正式安装版本。
- **检查失败或访问被拒绝**：检查网络或代理对 GitHub 的访问；普通 403 不再统一解释为限流，这不表示当前已是最新版本。
- **限流**：显示可重试时间，等待期间重复点击不会继续发起检查请求；没有服务器等待时间时使用短暂冷却。
- **文件校验失败**：不会运行该文件，重新下载。安装文件位于当前用户数据目录下的 updates 缓存，与银行 PDF 目录分开。
- **版本不兼容或发布文件异常**：查看提示原因，不手动替换主程序中的 DLL 或认证组件。

目前安装包未配置产品签名证书。SHA-256 只验证下载文件的完整性，不等于验证了发布者签名；Windows 可能显示信誉提示。

## 维护者如何发布

更新源码并推送到仓库 `main` 后，GitHub Actions 自动检出这次推送的最终提交，运行测试、干净构建和载荷检查。只有全部通过且安装 EXE、发布清单、校验文件上传核对完整后，才公开正式 Release。测试失败时旧发布版本保持可用。

所有 main 推送都会触发，包括仅修改文档的推送。用户需要等待构建和发布完成，再重新检查或下次启动应用；推送源码并不意味着安装包已经立即可下载。

基础版本位于 `build/version.json`，实际自动发布版本为 `主版本.次版本.(基础补丁号 + 工作流运行序号)`。同一次任务重跑保持同一版本，失败后可以有版本空号。源码不会为了补丁号自动产生机器人提交。以后修改基础版本或工作流计数方式时，不得回退、碰撞或超过 Windows 文件版本范围。

工作流失败后可以在 GitHub Actions 中重跑原任务。未公开的同身份草稿可以恢复上传；已经公开且完整的版本不会被重跑覆盖。发布保留 GitHub 的自动最新正式版本选择（make_latest:legacy）和单调版本检查；客户端跟随最新正式发布入口并按数字版本比较，绝不推荐低于或等于当前版本的安装包。主查询不再枚举全部历史发布；最新清单损坏或不兼容时明确报错，不自动选择较旧候选。

Release 提供三个文件：

- `UsbWebLauncher-<版本>-win-x64-setup.exe`
- `release-manifest.json`
- `SHA256SUMS`

公开仓库的使用者无需 GitHub 账号、Git 或编译环境。写入发布所需权限只在 CI 发布任务中使用，不能将个人 token、PIN 或签名私钥编入客户端。正式发布文件不可原地替换；发现问题后撤回问题版本，并发布更高版本修复，已安装客户端不自动降级。

构建入口与工具要求见 [构建说明](../build/README.md)。自动测试和发布成功不能替代真实 Windows 安装、UAC、Key 和银行页面验收。
