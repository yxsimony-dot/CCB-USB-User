# 统一 PIN 与银行登录流程调整（2026-10-09）

用户确认所有 Key 使用相同 PIN，并明确要求取消程序本地按 Key 匹配认证配置的步骤。识别规则仍是 USBSTOR 加同设备关联光盘名称或卷标包含 CCB。原检测任务中“不调整认证”的范围限制被这次后续指令扩展。

## 实现

- 当前发布配置使用 `BrowserNative`。移除固定证书、CSP、密钥容器和 token 解锁配置；启动不读取 Key 验证印章，不调用 CryptoAPI/PKCS#11 解锁接口。
- 使用原有 Windows 凭据目标保存和读取统一 PIN，无需重设。保存与删除 PIN 不再依赖旧验证印章文件。默认 `ConfiguredToken` 模式兼容旧配置。
- 对授权银行 HTTPS 端点的当前证书请求，唯一候选直接使用；多个或没有候选时沿既有浏览器选择流程继续，不枚举硬件身份或轮流尝试 PIN。
- 原生输入继续使用受保护组件、可信进程和控件匹配、一次尝试、导航/插入周期关联及大小写处理。银行和驱动执行实际认证；此模式不声称本机已验证 PIN。
- 无证书请求的成功页面可继续网页登录，并允许其随后发起的证书请求。设置 PIN 或安装环境暂停业务后，旧页面不能使用旧 PIN；新 PIN 只在显式启动后生效。
- 认证失败优先显示真实原因，不再被“准备完成，请继续”覆盖。流水和回单导出实现没有修改。
