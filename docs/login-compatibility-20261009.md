# 登录通用兼容与导航竞态修复（2026-10-09）

用户要求减少换 Key 时因模板差异反复改代码，授权放宽控件识别规则。

## 现场证据

上一轮修复后，原生认证日志于 16:10:58 记录 Success / Completed，候选与匹配各 1，证明 PIN 输入及确认已经完成。之后网页登录日志在一次检查中记录旧入口地址和 unsupported，随后的诊断也仅返回 unsupported。脚本的诊断分支只有地址不匹配才如此返回，结合认证跳转，表明异步检查可能用旧地址执行于新文档。旧代码未在失败分支核对导航变化，直接停止尝试。

## 实现

- 原生备用识别不再绑定 1010/1 等固定编号：在当前可信窗口内匹配唯一启用的可见 Edit 与唯一“确定/确认”按钮，记录实际正控件编号。空标题要求唯一“取消”按钮提供额外证据。保留配置组合优先、进程父子关系、用户、会话、完整性、重抓及单次输入；不读取 Edit 内容作为识别证据。
- 网页按可见“登录密码”用途（placeholder、aria-label、关联 label 或已有 LOG_PWD 标识）与同表单唯一“登录”按钮定位。不再要求固定 form ID/name、控件名称、证书登录标题、恰好两个可见账号框。支持账号信息隐藏或没有账号框、隐藏模板副本与额外信息字段。
- 现有账号字段仍记录文档内引用和值以检测填写过程中的账户切换。保留银行地址范围、同源同表单 POST、页面原有点击处理、手工已填密码不覆盖、歧义拒绝及单次提交。
- WPF 适配器跟踪 NavigationStarting/Completed 的导航 ID 和文档代次；检查前后、诊断后发生跳转时返回等待，导航使旧票据失效。同地址重载也不能沿用旧票据。稳定页面明确不支持才返回不支持。
- 新诊断只增加当前 origin/path 与导航状态，不写 URL 查询串、PIN 或票据。
