# 登录后弹窗结构探索

用户已确认自动填写并提交登录后成功进入主页面。截图有企业手机银行推广层、温馨提示和一个独立公告窗口，均可能出现，也可能不出现。最终处理要求是出现时处理、不等待三个弹窗、不把清理完成作为后续业务的前置条件。

## 当前限制与采集方式

当前浏览器工具连接不可用，尚未连接或读取实际主页面 DOM。现有 certificate-page-login.jsonl 只覆盖登录前和提交结果。用户希望避免手动打开开发者工具，因此在原程序增加临时只读结构采集器；本次不是正式的自动关闭功能。

WebView2 导航完成后，独立的低优先级后台定时器每两秒请求一次结构快照，每次导航最多 60 次。不在登录或业务调用链等待采集结果；采样尚未返回时丢弃重叠采样，结果未变化时不重复写入。错误局部隔离，程序释放时停止采集并解绑。该定时器仅用于本次探索；正式弹窗处理仍采用新窗口事件及 DOM 变化事件，不等待弹窗出现。

探针同步返回，无轮询或等待。只检查 HTTPS 标准端口的建行 /NCCB/ 页面与同源子文档，最多 16 个文档、4 层、每文档 30 个候选。记录脱敏后的 tag/id/class/role/type、可见性、有限祖先结构和固定公告标题标记；onclick 仅提取函数名，不输出参数。没有读取输入框值、Cookie、浏览器存储、整页 HTML 或输出正文；URL 不包含查询参数及 fragment。独立公告只记录新窗口请求的网址结构，保持原来的打开行为。

输出位置为当前用户本机 `%LOCALAPPDATA%/UsbWebLauncher/logs/popup-structure.jsonl`，每次启动首次写入清空上一轮采集，文件上限 512 KiB。采集不会点击、关闭、拦截窗口或改变页面。日志仅用于核实实际弹窗选择器及所属 frame，不能根据本地模拟用例宣称已经适配真实主页。

用户重开后确认进入主页。2026-09-30 14:21 的结构结果已保存到同一验证目录 `live-discovery.json`。独立窗口请求为 `https://www.ccb.com/chn/html1/subject/25/10/1029wy/html.html`，`userInitiated=false`；右下提示位于同源 `/NCCB/NECV6B2BMainPlat_09_LH` 文档，关闭元素为 `#noticeTip .ccbWinHead a.ccbWinColse`，可见且属于 warm-notice 标记。

主页面有多个包含“企业手机银行”的菜单、页脚和隐藏模板，不能把这些文本匹配作为自动关闭依据。用户明确确认中央手机银行推广当前仍显示。探针同时发现可见 `iframe#win_0000` 的声明地址无法归类为 HTTP(S)，被第一版跳过；并且 `.mob_drain/#top_sjyl_type1` 仅采集到隐藏标题，未覆盖完整关闭结构。因此第三个推广层尚未可靠定位，不能据现有记录判定它未出现或直接关闭任意 close 控件。

下一次诊断修订需区分动态/继承空白 frame 与外域 frame，检查浏览器允许访问的实际文档来源，不执行 frame src 中的代码；对已知推广容器追加有界的纯结构子树以核实真正关闭元素。仍只采集、不修改网页。

修订已实现：frame 增加固定 srcKind 与 inspection 分类，允许对动态声明的当前可访问文档作实际来源验证，保留同源、深度和数量限制；推广区域每文档最多 3 个、合计 60 个去重结构节点，图片只记录 origin/path，事件只记录函数名，支持实际网页的 colse 拼写。五项新增回归均先失败后通过；最终全量 .NET 850/850、脚本 43/43 通过，发布构建成功。用户确认关闭程序后，已更新原目录 App DLL/PDB 并逐一核对 SHA-256，唯一快捷方式和唯一主程序 EXE 均保持原位。状态与哈希见 `expanded-result.json`、`expanded-staged-sha256.json`、`expanded-deployed-sha256.json`。实际第三个弹窗仍待新的结构采集确认。
