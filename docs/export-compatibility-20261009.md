# 合并导出页面兼容修复（2026-10-09）

## 现场根因

当前账号的银行主框架为 `/NCCB/NECV6B2BMainPlat_08_LH`，首页子框架为 `_08_FW`。旧流水、回单脚本只允许 `_09_LH/_09_FW`，所以真实首页虽已加载，两条脚本都返回 `unsupported/home/home-not-found`。C# 下载来源与回单下载端点也存在相同版本硬编码。

修正路由后，实机进一步发现日期页解析竞态：日期输入框先出现，隐藏的 `ACC_NO` 字段稍后才被解析。旧脚本立即报告 query ready，随后报 account-mismatch。只在页面内部对比字段，待页面完整后，列表选择值与日期页字段七段全部精确相等；因此没有修改或放宽账户一致性判定。

## 修改

- 两个 JS 导出器的文档遍历、当前文档验证和表单 action 支持 `NECV6B2BMainPlat_<数字版本>_(LH|FW)`，不再绑定单一版本。
- 两个导出器在业务文档达到 `readyState=complete` 后才校验和操作控件；流水 inspect 同样等待。
- 流水下载目标保留 LH 打印端点，来源支持数字版本的 LH/FW；回单下载支持数字版本的 `NECV6FileDownload_<数字版本>_LH`。
- 保留 HTTPS、批准银行域名和同源、账户日期核对、防重复点击、首页导航、第一页回单、空流水停止、PDF 文件检查和原有命名。
