# 流水 PDF 按公司和账户命名

用户要求新文件名为 `公司全名建行账号后4位.pdf`，不加年月或额外分隔符。名称完整保留“分公司”“工会”等后缀，账号尾号保留前导零。同名文件继续加 ` (2)` 等序号，不覆盖原文件；Windows 禁止的文件名字符替换为下划线，过长名称明确拒绝而不截断。

首页和交易结果页均能提供名称与账号。为与实际导出的第一条账户对应，实现使用本次查询结果中 `jhform > table#headTable` 的“账号”“账户名称”相邻单元格，并与 `checkedAccno`、`checkedAccName`、本次选中 `ACC_NO` 的复合值交叉核对。五份既有真实结果结构中的对应关系均已核对，脱敏技术证据见 `artifacts/verification/statement-pdf-naming-20260930/naming-dom-evidence.json`。不把整个 ACC_NO 复合值直接截后四位。

查询结果就绪后先执行只读 identify，传回公司全名和账号末四位，再创建下载接收器。下载前和菜单事件后再次校验名称一致；缺失、歧义、截断或不匹配时停止并提示。完整账号不回传到宿主，名称/尾号不加入诊断日志；命名信息只用于本次文件和已有的成功提示。

仅调整命名及对应身份传递，原查询、菜单、下载完成与 PDF 验证逻辑保留。另一任务同时实现“下载目录”，共用下载接收器的接口已协调，由下载目录任务统一全量验证、发布及更新清单，本任务不单独覆盖 App DLL。

相关策略/文件/协调器测试 45/45 通过，其中新文件名用例在旧实现上先观察到失败。最终浏览器回归及合并部署结果见同目录 result.json。原年月命名版本已实机验收；新命名规则须按新版本实际结果确认。
