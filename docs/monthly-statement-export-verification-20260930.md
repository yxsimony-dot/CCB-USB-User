## 实现范围

“导出流水”只由用户主动点击。点击时固定本机当前年份和所选月份，进入活期账户、只选择第一条账户，通过网页原有交易明细和查询处理器提交整月日期，再使用属于“下载全部”的原 PDF 菜单动作。没有屏幕坐标操作，没有构造未经验证的银行 HTTP 请求，也没有重新生成 PDF。

下载阶段通过同一 WebView2 环境和 profile 的受控子窗口承接银行原始新窗口请求，不用 GET 替换 POST。只接受该子窗口内符合来源及 PDF 类型的下载，先存到桌面的唯一临时文件，收到完成事件并验证 `%PDF-` 文件头后，无覆盖地移动为 `活期流水_YYYY-MM.pdf`，重名自动加序号。

月份计算覆盖闰年；未来月份拒绝提交，当前月份仍为整月。导出状态独立于登录状态，运行期间禁止冲突操作；每个网页提交仅执行一次，等待有时限，关闭时取消并解绑接收器、关闭子窗口、清理本次临时文件。日志仅记录固定步骤/状态，不记录 PIN、Cookie、账号、流水内容或网页原文。临时结构采集器已移除自动接入，证据文件保留。

为验证事件顺序，在工作区外建立隔离 WebView2 测试宿主及独立 profile，使用本机 loopback 的合成 POST/PDF 附件，无网银会话、无用户账号/凭据，也未向用户桌面写测试文件。真实 WebView2 顺序为：new-window → navigation-start → NavigationCompleted(IsSuccess=false, ConnectionAborted, HTTP=0) → DownloadStarting → Completed。这证明原代码会在普通附件下载事件到达前判错并关闭子窗口。
