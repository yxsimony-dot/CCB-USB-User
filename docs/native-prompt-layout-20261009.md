# 新 Key 密码框识别修复（2026-10-09）

## 原因与现场证据

正式发布目录与上一轮暂存包中的 App/DLL/Broker 哈希一致，原快捷方式和运行进程路径也一致，确认旧文件已替换。旧 Broker 日志停在 CandidateSelection，CandidateCount=0、MatchingCandidateCount=0，尚未进入 PIN 输入。

新 Key 的实际 Win32 窗口为 #32770，顶层标题为空，输入框 Edit(1010)、确认按钮 Button(1)，按钮文案为“确  定”；取消按钮为 Button(2)。旧配置要求非空标题和 Edit(3743)/Button(4000)，因此在快照采集阶段就被丢弃。现场只读硬件预检再次复现 0 个候选；该预检不读取或发送 PIN。

## 修复

- 原有配置控件组合优先，增加实测的 1010/1 配对兼容；不混用两套控件编号。
- 备用组合必须只有一个可见 Edit，且可用、编号为 1010；只有一个文案去空白后为“确定”或“确认”的可见 Button，编号为 1。取消或多个候选均拒绝。
- 空标题只在备用组合验证完成后允许；非空标题仍遵循“验证xxx密码”规则。备用验证结果由选择器明确返回，不仅凭编号推断。
- 快照保存实际控件 ID；输入前和提交前重新采集并检查身份。保留可信进程父子关系、用户、会话、完整性、窗口类、焦点及单次尝试限制。
- 未更改 PIN 存储、大小写输入、USB Key 检测或导出流程。
