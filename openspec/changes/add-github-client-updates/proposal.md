## Why

用户把安装包交给其他电脑后，希望用户可以在应用内获取最新版本，避免每次手动传递 EXE。用户已确认：`main` 每次更新且测试通过后自动发布；已安装 1.0.0 的用户先手动安装一次带更新功能的版本。

## What Changes

- 增加“检查更新”入口，并在应用启动后后台检查一次；显示当前版本、新版本、更新说明及下载进度，用户自行决定安装时机。
- 给公开仓库 `yxsimony-dot/CCB-USB-User` 增加自动发布流程：每次 main push 检出对应提交，测试、构建完整安装包并生成校验清单，成功后发布正式 GitHub Release。无需用户逐次指定版本号。
- 自动生成可比较、可追溯的版本；解决同一任务重跑、发布中断以及多次推送完成顺序不同的问题。未通过验证的构建不对客户端发布。
- 客户端从固定仓库查找稳定版本，下载并验证完整安装包，然后调用现有安装器完成 App 和认证组件整体升级。
- 业务进行中允许检查和下载，安装前必须回到业务空闲状态；复用正常退出与安装恢复流程，保留 PIN、下载目录和 PDF。

## Capabilities

### New Capabilities

- `github-main-release-publishing`: main 自动构建发布、自动版本、发布完整性与重试约定。
- `client-update-check`: 客户端更新发现、版本展示、下载验证和失败状态。
- `installed-update-handoff`: 空闲状态检查、正常退出、安装器交接及首次更新入口迁移。

### Modified Capabilities

无已归档规范需要修改。复用未归档变更 `package-windows-installer-with-upgrade-support` 已实现的安装器与清单；该变更原先将自动发布/检查更新排除在当期范围，本变更新增这些行为，不反向改写其历史验收记录。

## Impact

涉及 App 菜单、版本/更新状态与正常退出协作，构建版本参数和发布清单，以及新的 GitHub Actions 发布工作流。目标继续为 Windows x64、当前 Windows 用户安装；GitHub 仓库保持公开，客户端不携带 GitHub 写入凭据，也不需要 Git、Node 或 .NET SDK。

现有安装器是交互式安装，可能需要同账号 UAC；本期不做静默安装、银行业务热替换、差分更新或客户端编译源码。全新电脑真实安装与升级验收仍须单独执行。
