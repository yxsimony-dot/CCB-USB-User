## Context

需求见 proposal.md。已有流水实现包含 StatementExportMonth、CcbStatementExport.js、StatementExportCoordinator、WpfStatementDownload、StatementPdfFile 和 DownloadDirectorySettings。用户最终要求将流水命名改为 `月份-公司全名-建行账号后4位-对账.pdf`，回单命名改为 `月份-公司全名-建行账号后4位-回单.pdf`。月份取本次选择，以两位数字 `01`～`12` 表示，不带“月”字。这一要求覆盖本变更此前不加月份及“流水命名不变”的约定；历史验证文档保留当时事实。

用户已确认“全选”仅选当前页、预览/打印会触发下载，并明确只需要第一页。截图提供页面流程和筛选默认值，但没有回单控件标识、处理器或下载请求证据。当前实时浏览器连接报错，旧本地采集只有流水资料；WpfStatementDiagnostics 已不自动接入，没有现成诊断开关。

## Goals / Non-Goals

**Goals:** 在当前登录 WebView 会话中稳定执行用户已确认的流程，并复用已验证的月份、首页、目录和文件完成策略。以实际页面证据建立回单专用适配，不扩大采集范围。

**Non-Goals:** 不遍历分页，不合并多个分页文件，不点击“下载全部”，不改银行生成的 PDF 内容，不增加年份/账户选择 UI，不改 PIN、认证、公司展示或流水业务范围。

## Decisions

### 1. 先取得页面证据，再实现网页适配

实施阶段先确认是否恢复了可连接页面。若仍无法直连，临时接回现有有时限、体积上限和同源限制的结构采集器，扩展回单固定标签白名单，并观察用户在原程序的一次人工查询和下载。输出仅含字段名称/类型、控件标识、固定标签、处理函数名、frame 层级，以及请求方法、去除参数值的地址结构、响应类型和下载生命周期。不采集 PIN、Cookie、正文、输入值、完整账号或交易明细；需要研究脚本时限定相关静态逻辑，不保存整页内容。

保留脱敏证据用于测试，交付前移除自动采集接入。截图不能代替 DOM/事件证据；不得猜测选择器、隐藏参数或复用流水路径白名单冒充回单路径。相比坐标点击和重建 HTTP 请求，调用银行原控件处理器能保留已有校验与动态表单状态。

### 2. 独立回单流程，复用小范围公共能力

增加回单协调器和页面适配脚本，使用独立页面状态键及每次新 runId。流程为首页就绪 → 账户查询 → 电子回单查询 → 配置并提交查询 → 核对第一页 → 全选第一页 → 触发预览/打印 → 等待文件完成。

首页检测优先提取现有已测试的小型公共逻辑；回单的查询页、结果页和下载控件保持独立匹配，不用不断增加分支的流水脚本承担所有业务。账户以流水相同的第一条活期账户为准，通过本次页面账户信息匹配回单选择项，不能假定回单下拉框的第一个选项就是同一账户。

显式设置截图中的批量查询、打印状态全部、交易方向全部、PDF、合并下载是；清空可选金额和凭证筛选。填写后回读核对，提交原“确定”处理器。以本次查询的账户/起止日期和页面代次证明结果关联。新查询必须落在第一页；发现其他页码或无法确认第一页时停止，不通过自动翻页补救。单页且没有分页栏的识别必须有实页证据。

全选需确保所有可选结果行已经选中，已全选时不再次切换。查询、选择与打印动作都在调用原处理器前标记为已消费，轮询只检查状态，不重复提交。没有结果时显示该月无回单，不产生空文件。结果页标题可能仍为同一业务页签，必须用控件结构与状态判断，不能仅靠标题。

### 3. 单一活动导出上下文

两个导出按钮共用一个活动任务门闩，入口在首次 await 前占用；忙时重复或交叉点击忽略，不排队。不能让两个 exporter 各自 IsBusy，或由任一 StateChanged 错误解除另一任务的忙碌状态。

每次开始固定月份、年份、可写下载目录和导出类型；本次账户确认后生成不可变命名身份。保持现有界面忙碌互斥，月份、下载目录、环境/PIN 等冲突操作同步禁用。关闭时先取消并等待导出清理，再销毁浏览器；只有当前任务拥有者可以释放状态。进度明确标注“回单”和“第一页”，不显示“全部月份回单已导出”。

### 4. 下载承接与文件命名

在点击预览/打印前注册本次专用下载接收器。根据实际证据选择父页附件或同环境/profile 子窗口下载路径，并以对应 frame、origin、已触发动作及当前运行上下文约束归属。流水接收器当前仅认领指定 LH 新窗口，不能直接照搬到未知回单地址；只为观察到的回单路径增加匹配，不放宽成接管整个银行所有下载。

如有子窗口，保留原 NewWindowRequested/POST 语义；不改写为自行 GET。复用 PDF 媒体类型/文件头验证、独立临时文件、完成后原子命名、失败清理和碰撞序号策略。流水为 `月份-公司全名-建行账号后4位-对账.pdf`，回单为 `月份-公司全名-建行账号后4位-回单.pdf`；月份使用本次不可变月份快照，显示为 `01`～`12`（两位数字，不带“月”字），分隔符使用半角 `-`。例如 `09-示例公司-建行0507-对账.pdf`、`09-示例公司-建行0507-回单.pdf`，冲突分别使用 `…-对账 (2).pdf` 和 `…-回单 (2).pdf`。只应用于后续导出，不重命名已有文件。文件名月份及类型属于本次不可变上下文，不能依赖下载完成时的界面选择、可变化的顶部公司展示或最近一次账户缓存。为月份前缀、连字符及两字业务后缀重新计算文件名长度预算，保留账号末四位中的零，不静默截断公司名。

相比新增一个通用银行自动化框架，本次只提取必要的互斥和文件策略，避免扩大已验收流水的变更面。

### 5. 有界等待和验证

沿用总任务 120 秒、页面阶段 30 秒、下载 90 秒的上限（最终受总时限约束）；超时、取消、歧义、会话过期、账户或月份不匹配停止并提示，不重放查询或打印。释放监听、deferral、子窗口及本次临时文件后才能开始下一次导出。

用脱敏真实结构建立 DOM fixture，覆盖多页但仅操作第一页、旧页签重入、正确选择状态、账户/日期匹配和一次下载。以模拟页面和 WebView 下载测试验证实现；真实银行结果单独记录，不能由本地测试推定。

## Risks / Trade-offs

- [回单实际下载入口与流水不同] → 在网页适配开发前完成有限采集，以观察到的事件链路确定承接方式。
- [重复查询复用旧页签或保留旧筛选] → 每次返回首页、显式覆盖筛选、核对本次结果与第一页，旧状态不得触发打印。
- [同一月份有多页] → 用户已选择仅第一页，界面明确提示这一范围，不扩展为跨页下载。
- [两个按钮竞争同一页面/下载] → 单一活动任务拥有全部监听和状态，首次 await 前抢占，完成清理后释放。
- [银行无回单、日期范围拒绝或登录失效] → 可理解的失败/无结果提示，不生成伪 PDF，不改月份范围绕过限制。

## Migration Plan

先完成页面采集与对应测试，再交付功能。运行相关 .NET/Node/WebView 回归、OpenSpec strict 校验和独立审查，发布到新暂存目录。替换前确认原程序关闭，备份并仅更新实际有差异的发布文件，核对哈希及唯一快捷方式。保留已验收 PIN 版本；需要更新程序集绑定时通过原“安装环境”完成。验证单页、多页仅第一页、重复导出、重名及与流水交替操作；真实验收未完成的任务保留未勾选。失败可恢复该次发布备份。

## Open Questions

无待用户决定的产品问题。待现场确定的技术事实是回单 frame/控件/处理器、第一页标识和下载来源；这些属于已安排的首阶段采集任务，不改变只导出第一页的行为约定。
