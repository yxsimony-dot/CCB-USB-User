## Context

动机见 proposal.md。LauncherViewModel.CanStartBusiness 仅允许首次、准备恢复及错误重试，MainWindow 的按钮文字固定。App 拦截 Closing，等待 operationGate 后顺序释放导出、ManualLauncherActions 和运行时，ApplicationShutdownSequence 没有总期限。网页登录提交有不可取消等待，多个 DisposeAsync 无期限等待活动任务或锁；尚未取得用户当次卡住的运行栈，不能将其中任一路径断言为唯一根因。

WpfWebView2Control 的释放只解绑事件，未真正销毁 WebView2；默认环境复用浏览器数据。仅把页面导航到空白，或复用原控件重新绑定，都不足以保证换 Key 后会话隔离。

## Goals / Non-Goals

**Goals:** 分离应用寿命与业务会话寿命；支持可取消、可隔离的重复业务；保证关闭有总期限；用故障注入和真实换 Key 验证。

**Non-Goals:** 不模拟银行端注销或撤回事务，不重置硬件 PIN 错误次数，不终止第三方银行软件或外部浏览器，不更改导出规则和文件命名。

## Decisions

2026-10-10 用户补充：物理拔出本轮 Key 与手动中止具有相同效果，替代先前“同轮插拔自动继续”的约定。应用会话级设备监听包装器在向旧协调器传递快照前确认物理移除，即刻撤销本轮授权并安排 UI 中止。监听错误和物理设备仍在时的元数据缺失不等同拔出；首次未插 Key 的等待维持原行为。移除一经确认，不再向旧协调器转发后续快照，快速插回也需显式新启动。

### 1. 明确会话状态与操作入口

采用 Idle → Active → Stopping → Idle，任意状态均可进入 Closing；清理失败进入 StopFailed，只允许关闭及必要的失败提示，不开始第二会话。Active 内部仍使用已有等待设备、认证、就绪、错误、导出子状态。启动前前置检查失败回到 Idle；一旦会话开始，按钮承担中止职责，不通过“成功提交登录”等不可靠信号猜测业务是否结束。

按钮文字和 CanExecute 由会话状态驱动，中止路径独立于普通 IsBusy 与 AsyncDelegateCommand 的启动执行锁；受理中止先改变状态，防止同步重入。已有同轮重试保持原语义，不与中止按钮混用。活动期间 PIN 维护先中止，本机配置仍属于应用级对象。

### 2. 每轮独立资源所有权与代次

应用级保留窗口、配置、PIN 存储及环境管理入口。每轮拥有 CancellationTokenSource、唯一代次、USB 监听/认证编排、网页登录自动化、浏览器、公司显示、导出器和子下载控制器。中止开始立即使代次失效、撤销认证与页面操作授权，然后取消并停止工作；所有异步结果和 UI 回调发布前验证所属代次。收到取消不能自动创建新认证尝试或重复提交。

采用统一 EndSessionAsync(reason) 编排中止和退出；不要简单复制现有 DisposeRuntimeAsync。按依赖先广播撤销、停止页面操作和下载、解绑来源，再释放设备与认证资源；独立清理失败不阻止后续必需释放。不能持有启动锁等待中止完成，或让中止先等待一个尚未取消的启动任务。

### 3. 真正释放浏览器并隔离下一轮

MainWindow 浏览器位置改为可替换的容器；中止时停止导航、释放本轮下载子控制器及主 WebView，在 UI 线程完成所需的控件生命周期操作。新轮创建新控件及独立的本应用会话数据目录/环境，重新安装已有本地银行扩展并绑定认证处理器；初始和中止后的空白状态不提前导航或进行业务 USB 枚举。

不依赖仅删除 Cookie 或 Navigate(about:blank)，因为仍可能复用网页存储、证书选择或旧控制器。会话目录在确认不再使用后按本应用精确所有权清理，文件被占用时留待下次安全清扫，不阻塞中止。换 Key 实机必须验证不会继承上一公司登录；外部厂商缓存不可假定已清除，应以新轮认证与页面身份为证据。

### 4. 总期限与真正的退出兜底

中止和关闭各自从受理时建立八秒总预算，局部等待使用剩余时间，不逐层叠加超时。中止普通异步清理使用前 7.5 秒，预留 0.5 秒处理超时并显示 StopFailed；中止 UI 一秒内显示处理中，不能确认旧会话安全失效时不得假报成功或并行启动。

实机诊断已发现 WebView2 原生 iframe 事件解绑可以在 UI 线程触发进程级异常；已移除该逐帧原生解绑路径，由主控件统一销毁。对其他不可恢复的原生同步阻塞，中止也在触及资源前启动本轮独立八秒看门狗：若 UI 可以响应则正常完成或显示 StopFailed 后取消；若 UI 已卡死无法显示失败，期限耗尽时退出本应用。中止与关闭的看门狗独立，完成中止不得取消已启动的退出兜底。

退出在触发任何可能同步阻塞的 Cancel/COM 调用之前，安排独立于 UI Dispatcher 的看门狗；优先正常关闭，期限耗尽后仅终止本应用进程。不能仅包一层 WaitAsync 就承诺 UI 线程同步释放卡住时也能退出。看门狗必须随正常退出取消，并在进程级子进程测试中验证；不得按进程名称批量杀 WebView2 或厂商程序。重复关闭共享同一截止时刻，Closing 优先于 Stopping，退出完成不再重建会话。

### 5. 下载与提交边界

中止前已经原子发布的 PDF 保留；未完成下载取消并清理本轮临时文件，若清理受文件锁阻挡，记录并延后处理。代次撤销后不得由迟到完成发布文件或启动回单。已送入银行或原生控件的提交不能宣称撤回；中止只保证不再发起后续动作。

### 6. 诊断与验收

记录代次编号、开始/中止/退出、阶段、耗时、取消/超时结果，不写 PIN、完整身份、表单值或 URL 参数。新增可控永不完成任务和迟到回调测试，退出兜底用子进程验证；正常和故障路径分别验收，不能用“窗口隐藏”代替进程退出证据。

## Risks / Trade-offs

- 浏览器环境隔离可能增加每轮启动时间及扩展初始化 → 按实际耗时验证，保留本地扩展包，不复用银行登录状态。
- 第三方调用忽略取消或同步卡住 → 阶段诊断、总预算、独立退出看门狗；中止失败不允许新会话重叠。
- 旧事件覆盖新状态或迟到下载继续落盘 → 代次校验、事件解绑、下载发布边界共同保护。
- 强制退出遗留临时文件 → 仅清扫本应用拥有的会话目录和未发布文件，保留成功 PDF、PIN 和配置。

## Migration Plan

先完成回归和故障注入，再发布到独立 staging。备份正式 App 及实际改变的依赖文件，关闭旧应用后替换并核对哈希；若旧应用无法正常退出，只按核实的本应用 PID 和路径处置。更新认证组件的 App 哈希绑定。通过正常启动、中止、同 Key 重启、换 Key 重启及退出验收后交付；失败则恢复备份并恢复对应认证绑定。不得覆盖 PIN 或下载配置。
