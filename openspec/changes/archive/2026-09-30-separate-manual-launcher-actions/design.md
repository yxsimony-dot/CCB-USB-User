## Context

动机及范围见 proposal.md。当前 App 初始化组合运行时、绑定命令后直接调用 LauncherCoordinator.StartAsync。ComposeAsync 本身不会开启 USB 监听或初始化网页，因此可以保留组合过程并延后 StartAsync。

现有 LocalPinCommands 在设置时自动补装组件，保存后调用 ResumeNavigationAfterAuthenticationSetupAsync。另有隐式路径：SaveFixedAsync 通知 AuthenticationCoordinator.ReportPinProvisionedAsync，后者在设备存在时执行 StartCycleAsync。因此仅移动启动调用或删除导航回调不能完整隔离准备操作。

StartAsync 是首次启动且幂等；RetryAsync 面向已有错误；ResumeNavigationAfterAuthenticationSetupAsync 面向设置后的恢复。现有 AsyncDelegateCommand 只防止单个命令重入，初始 PIN 按钮可用条件依赖认证阶段，需补充应用层状态。

## Goals / Non-Goals

**Goals:**
- 在应用层区分界面初始化、准备操作和显式业务运行，尽量调用已有服务。
- 用少量编排状态和明确命令入口处理待启动、准备中、等待明确继续、业务运行及关闭状态。
- 保留现有认证流程和所有已验证底层行为。

**Non-Goals:**
- 不重写 LauncherCoordinator / AuthenticationCoordinator 的设备识别、认证算法或状态转换规则。
- 不新增停止/重启业务、自动重登、业务插件系统或每次插入都必须点击的机制。
- 不更改 PIN 存储、证书/主机配置、密码窗口检测或输入方式；不扩展环境安装范围。

## Decisions

### 1. 保留运行时组合，把首次启动移到业务入口

App 启动仍读取配置、创建窗口及运行时、绑定命令并读取非秘密环境健康状态；完成后显示业务未启动。业务入口首次调用原 StartAsync。已有错误调用原 RetryAsync；有待应用设置时先应用设置通知再走原恢复入口。不得用重复 StartAsync 代替恢复，也不为每次点击销毁重建运行时。

相比只在 XAML 加按钮，这能解决原启动自动运行；相比重写协调器，影响更小。初始化失败的重试只恢复初始化。关闭与 smoke-test-no-devices 仍保持其既有清理和无硬件访问契约。

### 2. 在应用组合层隔离 PIN 保存的业务副作用

保留 SaveFixedAsync 写凭据和待验证标记的实现。在应用组合层提供生命周期观察器适配器，保存成功仅记录最新未消费的凭据变更，不立即向认证协调器转发 ReportPinProvisionedAsync；去掉设置命令自动调用恢复导航的联动。

显式业务动作消费待处理通知，再调用既有业务入口。重复保存合并为当前有效凭据的一次待应用通知；普通重复点击不能重放通知。删除时清空待处理保存通知，并立即转发现有删除失效通知，避免保留旧资源或旧凭据状态。

对于监听已经启动后的 PIN 维护，在应用层认证启动门适配处阻止设备存在通知开启新认证，保留最新真实设备信息，直到用户明确继续。真实设备移除及关闭清理必须继续传递；不得伪造设备移除/插入来重置认证周期。准备动作与明确继续使用同一编排门处理竞态。

业务因环境或 PIN 前置条件未满足而进入等待准备时，同样设置“等待明确继续”。环境安装完成只更新健康状态，不解除该等待；随后真实拔插也不得绕过它恢复认证。用户明确继续并通过已有前置检查后解除等待，恢复正常业务中的原有插拔响应。

保留认证协调器现有的“实际凭据更新后允许重新准备”语义，只延后其调用时机。页面已经 Ready 时，不强行改写原恢复方法的行为，不附带新增重新登录功能。

替代方案“仅删自动导航回调”仍会解锁；“禁用所有事件”会遗漏移除清理；“重建 runtime”会改变周期保护，均不采用。

### 3. 三个主要入口与现有维护能力

在现有网页上方操作区显示：

```text
[ 安装环境 ▾ ]  [ 设置 PIN ▾ ]  [ 启动业务 ]
环境状态 / PIN 准备状态 / 业务状态
```

前两项使用主按钮及二级菜单。安装主操作沿用安装/更新，菜单保留卸载；PIN 主操作打开原设置对话框，菜单保留更换/删除。环境健康检查未通过时 PIN 操作提示使用环境入口，不代为安装。

初始显示业务未启动，设备尚未检测时不误报连接状态；中央提示改为点击启动业务。设置入口不再被初始 WaitingForDevice 错误禁用。既有错误重试入口保留并区分初始化重试与业务重试。配置未启用认证时，业务手动启动仍有效，环境/PIN 入口显示不适用而不虚构认证能力。

### 4. 共用操作门与有针对性的验证

安装/卸载、PIN 维护及明确业务开始/继续使用应用层共用操作门和 UI 忙状态，保留底层认证忙时的限制。业务等待设备不应长期占有操作门。设备回调与待应用设置状态也需遵循同一隔离契约。

新增可替换依赖的应用层编排测试，验证“不会发生”的跨入口调用和首次启动/继续选择，不为 XAML 文案写实现镜像测试。复用原协调器、认证、PIN 和退出测试，完整执行现有测试套件。人工界面验收覆盖最小窗口、菜单、未启动与已插设备情形；硬件验证单独记录，不以自动化测试替代。

## Risks / Trade-offs

- [保存 PIN 隐式启动认证] → 同时隔离导航回调、生命周期通知和准备变更后的设备触发；测试已启动后的维护场景。
- [延后通知被重复消费或删除后重放] → 只记录当前待应用变更，在操作门内一次性消费，删除清空；失败不得自动反复转发同一事件。
- [延后设备事件影响清理] → 真实移除继续传递，只限制启动认证，保留真实设备状态及原清理规则。
- [按钮重复点击重置单次保护] → 复用运行时，明确 Start/Retry/Resume 选择，测试周期与提交次数。
- [原始状态文案/CanExecute 不适用于待启动] → 展示模型增加应用层状态，不修改认证核心状态含义。
- [更新应用后本机代理拒绝连接] → 按原路径/映像绑定策略重新安装，不放宽校验。

## Migration Plan

无需迁移配置和已保存凭据。实现后先运行自动测试及无设备冒烟，再构建独立发布目录用于 UI 验收，保留原包。真实设备验收记录新增入口的操作结果，已有 OpenSpec 变更的未完成硬件项目不自动勾选。部署新包时通过安装环境入口更新本机代理；回滚使用旧发布包并按原流程恢复匹配代理。
