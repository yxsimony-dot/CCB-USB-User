## Context

需求见 proposal.md。现有流水与回单分别由协调器、WebView exporter 和下载接收器执行，命令已经共用互斥门闩。单阶段 exporter 当前会将成功路径或 `null` 返回给调用者，空回单、失败和取消均可能返回 `null`，不能据此决定是否进入第二阶段。

已实现命名为 `MM-公司全名-建行账号后4位-对账.pdf` 与 `MM-公司全名-建行账号后4位-回单.pdf`，月份补零，重名加序号。流水空结果需要从既有真实页面证据确认；截图、等待超时或缺少预期控件不足以证明该月无流水。

## Goals / Non-Goals

**Goals:** 在已有两个导出流程外增加小型串行组合层，明确阶段结果和设置快照，保持从单次点击至全部清理结束的所有权。让页面空结果、部分完成和取消都产生准确可理解的反馈。

**Non-Goals:** 不合并两个 PDF，不增加月份/年份/账户控件，不改银行页面筛选和回单第一页范围，不扩展自动重试，不改 PIN 或认证逻辑，不重写下载与文件发布策略。

## Decisions

### 1. 用显式结果传递阶段状态

单阶段公开结果区分成功、空结果、失败、取消，携带与状态一致的已完成路径及用户可读消息。成功必须包含完成保存的路径；空、失败、取消不能通过同一 `null` 表示。组合层仅在流水成功且其清理任务已完成时继续。相较于读取界面消息或检查目录中是否出现文件，结构化结果不依赖文案，也不会把历史 PDF 误认为本次成功。

组合结果保留两个阶段的结果；流水成功、回单失败/取消/为空均保留流水路径。最终文案明确已保存哪些文件、哪些未完成，不用后一阶段的错误覆盖前一阶段成果。

### 2. 一次入口快照与完整串行等待

组合命令首次异步等待前占用现有共用门闩，并固定当前本地年份、所选月份、可写目录。两阶段均接收同一快照，不再独立读取当前月份、时间或设置。选中月份的整月范围与未来月份拒绝沿用既有逻辑。

先 await 流水完整任务，包括监听、临时文件和页面运行状态清理；成功后再次检查取消，再调用回单流程。回单流程负责原有“返回首页 → 查询 → 第一页下载”导航。阶段内部页面与下载等待继续使用现有有界时限；组合不能引入无界等待或自动重放。相较于在流水成功状态事件中立即启动回单，完整 await 可保证前一接收器已经释放。

### 3. 流水空结果是证据支持的终态

只接受当前运行、当前查询账户和日期关联的明确无数据标识或已验证空结果结构。另一实施任务先审阅既有脱敏实页资料，必要时补充受限证据；不得把仅有表头、旧页签、控件暂缺、登录失效、未识别页面或超时直接解释为空。

明确空结果在创建下载接收器及点击导出前返回，固定提示“流水页面为空，不需要导出该月份流水。”。组合随即结束，不调用回单，不导航回首页；页面 dispose 仅清理本次 JavaScript 状态，保留当前流水页。若当前资料不能证明某种空页结构，应明确失败或等待有界超时，不猜测空结果。

### 4. 单一 UI 入口与所有权

主窗口仅保留“导出流水和回单”导出按钮，现有单阶段服务可作为内部复用单元。组合拥有 UI 忙碌状态，阶段状态事件只更新进度，不能在中间清理后提前解锁。重复点击忽略，不排队；月份、下载目录和原有冲突操作保持禁用，直到组合 finally 完成。

窗口关闭先取消组合及活动阶段，再等待下载/页面状态清理，最后销毁浏览器。取消后不启动第二阶段，不执行额外首页导航。阶段已经发布的 PDF 不删除。

## Risks / Trade-offs

- [空流水结构资料不足] → 先检查证据与 fixture，将不确定状态保留为失败或等待，不以超时当空。
- [旧 `null` 返回值误触发回单] → 显式结果模型与覆盖所有状态的组合回归，只有成功分支可继续。
- [流水完成事件早于资源释放] → 等待完整阶段任务而非事件；用受控清理任务测试第二阶段时序。
- [两个阶段跨月或设置被外部更新] → 入口一次性快照，后续不重读年份、月份和目录。
- [回单失败后流水路径丢失] → 组合保存第一阶段成功结果并生成部分完成反馈，保留文件。
- [关闭与第二阶段入口竞争] → 阶段边界和导航前检查同一取消信号，共用门闩直到清理结束。

## Migration Plan

先完成结果模型、空流水判据与合成回归，再替换 UI 入口并接入组合。运行相关 .NET、Node、下载回归、独立审查和 OpenSpec strict 校验，构建暂存发布。部署沿用现有唯一快捷方式，确认程序关闭后备份并增量替换，记录文件哈希及必要的“安装环境”绑定刷新；保留可回滚备份。真实验收分别记录正常双文件、空流水留页、回单失败保留流水与重复点击；未实际观察的情况不标为已验收。
