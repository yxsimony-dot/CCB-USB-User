## Context

见 proposal.md。UsbDeviceMatcher 当前要求 VID/PID 与完整设备描述匹配；WindowsDeviceSnapshotMapper 已沿父链关联 USB、CDROM，并按光盘 PnP ID 关联卷。运行时记录尚未采集 Service，不能仅修改 JSON 或匹配表达式。

四份样本中，第 1/2 个通过卷标 CCB 命中，第 3/4 个通过设备名称 HDZB-CCB USB AutoRunDisk USB Device 命中；第 3/4 个型号、版本不同，实例 ID 却相同。实例 ID 只用于当前快照关联和生命周期管理，不能作为物理 Key 身份凭据。

## Goals / Non-Goals

**Goals:** 将已确认的两个条件准确贯通到枚举、匹配、配置和插拔生命周期；四个样本和具有相同结构的新型号均可识别。

**Non-Goals:** 不采集秘密，不改证书/CSP/PIN 或导出功能，不承诺自动登录所有 Key，不扩展对没有 USBSTOR 或没有 CCB 标记设备的支持。

## Decisions

### 1. 明确的建行匹配策略

在配置中引入明确的 CCB USBSTOR 策略选择。新发布的建行 profile 启用该策略；该策略必须同时要求当前 USB 节点的 Service 等于 USBSTOR，以及关联光盘名称或卷标包含 CCB，均使用 OrdinalIgnoreCase。Service 表示驱动服务身份，不比较本地化的“USB 大容量存储设备”显示文字。

不继续扩充 VID/PID 白名单，也不只凭 CCB 单条件放行。新策略不与旧 primary/additionalUsbDevices 做 OR；旧字段即使为兼容而保留，也不参与该模式的匹配或必填校验。无策略字段的旧 profile 保留旧行为，升级部署时显式迁移本应用 profile，避免隐式扩大其他配置的含义。未知策略报配置错误，不静默回退。

### 2. 保留设备关联边界

SetupApiUsbDeviceEnumerator 从当前设备读取 Service，贯通 WindowsDeviceRecord 和 UsbDeviceDescriptor。复用 mapper 的父链关系，只有该 USB 节点后代 CDROM 的名称，以及明确关联该 CDROM 的卷标可提供 CCB 证据。保留光盘 FriendlyName 与 BusReportedDescription 中非空名称，避免二选一漏掉标记。卷关联失败时不按盘符猜测归属；字段缺失不视为满足。

匹配不要求指定 VID/PID 值、型号后缀、REV、实例 ID 值、盘符或 CDFS。新策略的快照候选筛选须按 USB 节点与存储服务识别，不能继续强制包含 VID_/PID_ 字样；旧策略所需枚举兼容性保留。CCB 是忽略大小写的子串匹配，名称或卷标任一命中即可；不扫描任意文件、其他 USB 名称或全机卷标。USBSTOR 服务从存储节点读取，不从使用 cdrom 服务的光盘子节点读取。

### 3. 元数据就绪重试与取消

复用 WindowsUsbDeviceMonitor 的去抖、generation 和取消机制。业务明确启动后的首次枚举和设备变化刷新均可为未满足标记条件的 USBSTOR 候选进行有限刷新：默认间隔 1 秒、最多 5 次追加枚举，参数可注入以便测试。每次使用完整的新快照，不沿用先前 CCB 命中结果。候选离开、被新变化代替或退出时取消对应等待；达到上限后保持等待 Key，后续设备通知或正常手动重试可以触发新检查，不进行无限轮询。

第一次已满足条件时立即发布，无须等待所有卷挂载。重试不会制造新插入周期、重置认证尝试额度或重复触发业务。多设备保持原来的冲突/选择策略；新检测规则不引入“任意第一个 Key 即可信”的身份选择。

审查确认原认证入口将 `false → true` 当作新的插入周期，因此必须区分匹配证据缺失与 USB 节点真正消失。同一节点仍在时，有限重试期间不发布短暂的未匹配中间结果；节点真正消失时立即发布拔出。重试耗尽仍缺标记，则当前检测不匹配、停止导航并通过专门的元数据失效路径释放认证资源，但保留本次物理插入周期与已消费的认证额度。随后同一节点恢复标记只恢复检测，不自动再次读取/提交 PIN；实际拔出后才按原插入流程重新尝试。先前匹配节点 ID 仅用于判定生命周期，不能代替当前 CCB 匹配证据。

### 4. 验收分层

用四份只读采样提取最小硬件夹具，覆盖映射、匹配和回归；新增未知 VID/PID、型号和非 CDFS 的合成正例证明没有隐藏白名单。非匹配、跨设备 CCB、缺失属性、延迟挂载、取消和旧配置兼容均为自动测试。实机对四个 Key 分别确认插入识别和拔出清理；离线夹具通过不等于实机验收或登录通过。

## Risks / Trade-offs

- [普通 USB 设备也可具有 CCB 标记] → 用户已选择以此检测插入；命中不赋予认证成功状态，既有证书认证继续生效。
- [元数据加载超过有限重试窗口] → 保持等待并允许后续设备事件/用户重试，不缓存假成功，不为兼容退回白名单。
- [旧配置缺少策略字段] → 明确保留旧行为，发布迁移单独验证；不能只升级 DLL 而漏改识别策略。
- [物理 Key 共用实例 ID] → 不以实例 ID 区分账号，不缓存上次匹配证据；保留真实拔插取消机制。可靠的跨 Key 认证路由另行处理。

## Migration Plan

1. 增加测试与字段采集，完成策略、验证器、监测重试实现；更新源 profile 的检测部分并验证旧配置兼容。
2. 通过相关 .NET 测试和发布构建，复核 PIN 大小写输入、手动业务入口与组合导出回归；不触发真实认证作为检测测试。
3. 部署阶段按现有流程备份发布文件和 profile，只迁移检测部分；确认程序已退出再替换，保留证书/PIN 设置，按现有机制刷新受保护组件。
4. 四个 Key 逐一插拔验收并记录结果；当前采样不能代替此验收。发现回归时恢复整套备份及对应组件，不重设 PIN。
