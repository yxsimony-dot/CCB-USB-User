## Why

> 2026-10-09 后续范围更新：用户确认所有 Key 共用 PIN，并明确要求删除本机按 Key 匹配认证配置的步骤。下文原“不调整认证”限制仅描述最初检测任务；当前扩展采用 BrowserNative，无固定证书/CSP/容器预认证，保留银行认证、输入保护及手动启动。实现和验证见 `docs/browser-native-auth-20261009.md`。

2026-10-09 对四个实体 Key 的采样发现，它们均使用 USBSTOR 驱动，且同一设备关联的虚拟光盘名称或卷标包含 CCB。现有按 VID/PID 和完整型号描述匹配的方式会漏掉 uKeyCI800-K54，也不利于通用 EXE 支持同类 Key。

## What Changes

- 将建行 Key 插入判断改为两个必要条件：当前连接的 USB 大容量存储设备使用 USBSTOR 服务；该设备关联虚拟光盘的设备名称或卷标包含 CCB，忽略大小写。
- 不再将特定 VID/PID、型号名称、版本、序列号、实例 ID、盘符或 CDFS 作为建行检测的必要条件。
- 沿 USB 父子关系关联光盘及卷，禁止跨设备拼接条件；缺失信息时等待有限重试，拔出或退出后取消。
- 更新识别策略配置及旧配置兼容处理，保留手动“启动业务”的时机和原有取消、去重保护。
- 用四份采样与非匹配设备场景验收。该判断只表示检测到符合规则的 Key，不表示证书认证成功。

## Capabilities

### New Capabilities

- `ccb-usbstor-key-detection`: 基于 USBSTOR 与关联光盘 CCB 标记的建行 Key 检测、信息就绪重试和识别边界。

### Modified Capabilities

无。既有手动启动入口与认证要求继续有效，本能力替换其中设备匹配策略。

## Impact

- Windows 设备枚举、快照映射、Core 设备描述与匹配器、设备监听重试及相应测试。
- 配置模型、配置验证和源/发布配置的识别策略切换；部署需遵循现有发布与组件刷新流程。
- 不调整证书选择、CSP 容器绑定、PIN 保存/输入、流水和回单导出流程；跨 Key 自动登录适配属于独立任务。
