## Context

参见 proposal.md。用户已批准先部署临时诊断，再人工执行一次流程。本机浏览器工具无法连接，现有弹窗探针不能描述查询表单或 PDF 请求；当前程序可访问已登录 CoreWebView2。

## Goals / Non-Goals

Goals: 通过本机脱敏日志关联活期账户菜单、账户列表、日期表单、查询结果和 PDF 下载；为正式导出选择页面函数或同会话请求路径。

Non-Goals: 本次不自动执行查询、不实现导出、不读取 PIN/Cookie/响应正文、不把整个网站 HTML 或流水保存为日志。

## Decisions

- 使用独立 WebView2 诊断适配器，接入初始化和释放；所有诊断失败隔离，不改变登录或弹窗行为。
- 每两秒后台有界读取一次当前文档及同源 frame 的只读结构快照，忽略重叠采样及重复快照，最多 20 分钟。无需用户开开发者工具；不在业务链等待诊断。
- 结构脚本只输出技术标识、固定业务文字标签、字段名称/类型、表单动作元数据、处理函数名称及静态脚本路径。没有输入值、任意正文、事件参数或 JS 函数源码。只访问建行 HTTPS /NCCB/ 顶层和同源文档，支持继承 blank/动态 frame；严格节点/深度限额。
- 通过 WebResourceResponseReceived 观察已完成发送的请求，仅采集 URL 脱敏路径及参数名称、方法、状态、媒体类型和附件标记。POST 字段若无法无副作用地读取，明确标记不可用，优先依赖表单字段证据；不读取响应正文或完整请求头。
- 通过 DownloadStarting 和 StateChanged 观察下载方式、状态及媒体类型；不更改 Handled/Cancel/ResultFilePath，不记录默认文件名或实际保存路径。记录 NewWindowRequested 的脱敏地址，不改变默认行为。
- JSONL 日志限 2 MiB，单次进程启动清空旧诊断。写入队列有界、异步；记录开始/上限等固定生命周期事件以区分未运行、无变化、达到上限。
- 保持原导出按钮占位状态；人工操作直接在银行页面进行。

## Risks / Trade-offs

- [截图缺少接口] → 不猜测接口，不声明正式导出已完成，采集后决定下一步。
- [脱敏丢失业务代码/动态参数] → 保留字段名和有用结构；如仍不足，再有针对性分析，不记录令牌值。
- [DOM 较大、日志饱和] → 节点/文档/时间/输出体积上限；跳过静态资源请求，重复快照去重。
- [页面 JS 生成请求而非原生表单] → 网络元数据和原生表单可互补，未获取的 POST 字段明确记为未采集。

## Migration Plan

先测试、发布至工作区外暂存；关闭程序后只替换原发布 DLL/PDB，备份到系统临时目录并校验哈希。保留唯一入口和配置。用户重开并安装环境刷新绑定后，人工查询并下载一次 PDF。随后分析日志形成结论，移除临时诊断是正式导出实现的后续事项。
