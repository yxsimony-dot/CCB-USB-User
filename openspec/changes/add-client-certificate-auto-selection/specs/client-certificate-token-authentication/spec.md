## Purpose

为经过明确授权且精确配置的 HTTPS 目标提供可重复的硬件令牌客户端证书认证流程，同时限制 PIN 的使用范围、自动尝试次数和失败后的行为，避免秘密泄露、误选证书或令牌被连续错误尝试锁定。

## ADDED Requirements

### Requirement: 自动认证必须由精确配置授权
系统 MUST 只在配置同时明确指定 HTTPS 主机、端口、客户端证书标识、密码服务提供程序及其类型、密钥容器和密钥用途时启用自动认证。配置不完整、格式无效或目标不是 HTTPS 时，系统 MUST 禁用自动认证并显示可诊断错误。

#### Scenario: 完整配置允许进入自动认证准备状态
- **WHEN** 配置包含有效的 HTTPS 主机和端口、唯一证书指纹与身份约束、提供程序名称和类型、密钥容器及密钥用途
- **THEN** 系统进入自动认证准备状态，但在目标 USB Key 出现前不读取或使用 PIN

#### Scenario: 不完整配置被拒绝
- **WHEN** 自动认证配置缺少任一必需标识或包含非 HTTPS 目标
- **THEN** 系统禁用自动认证、显示配置错误，且不读取 PIN 或尝试访问令牌

#### Scenario: 非授权站点不能触发自动认证
- **WHEN** 页面或重定向向未配置的主机或端口请求客户端证书
- **THEN** 系统拒绝自动处理该请求，且不读取 PIN、不解锁令牌、不自动提交任何证书

#### Scenario: 附加 USB 白名单设备可以启动同一流程
- **WHEN** 当前设备不匹配主 USB 条目，但完整匹配一个附加 USB 白名单条目的 VID、PID、总线描述及已配置的虚拟光驱属性
- **THEN** 系统允许启动目标页面并进入同一认证准备流程，但仍只使用当前唯一活动认证配置精确匹配证书、提供程序、容器和密钥用途

#### Scenario: USB 型号匹配不能替代认证身份匹配
- **WHEN** 设备型号位于启动白名单，但其证书或密钥容器不匹配当前活动认证配置
- **THEN** 系统不得选择其他证书或猜测容器，并以可诊断错误终止本周期

### Requirement: PIN 必须通过本机受保护流程设置
系统 MUST 在没有可用 PIN 时提供独立的本机固定凭据设置入口，并且 MUST 只把 PIN 保存到当前 Windows 用户的 Windows Credential Manager。正常启动和 USB 插入流程 MUST 自动读取该固定凭据，不得要求用户再次在主程序或厂商窗口中输入。PIN MUST NOT 写入源码、启动配置、环境变量、命令行、普通文件、日志、遥测或错误消息。保存固定凭据不得同时伪造兼容性验证印章，但 MUST 写入与当前配置哈希绑定、且不能表示验证成功的非秘密待验证标记；普通的印章缺失、旧配置哈希或未知标记不得授权读取 PIN。

#### Scenario: 首次保存固定本机凭据
- **WHEN** 用户在独立本机设置入口输入并确认固定 PIN
- **THEN** 系统把 PIN 保存到当前 Windows 用户的 Credential Manager、清除旧验证印章、写入与当前配置绑定的待验证标记，并在 PIN 离开设置调用后清零短生命周期缓冲区

#### Scenario: USB 已插入时保存固定凭据后恢复真实导航
- **WHEN** 目标 USB Key 已经插入，启动流程因缺少固定凭据尚未初始化或导航浏览器，且用户完成固定 PIN 保存
- **THEN** 系统重新检查当前 USB 与认证状态并实际初始化、导航 WebView2，只有真实导航完成后才显示页面就绪；不得仅修改就绪状态而留下空白浏览器

#### Scenario: 首次设置验证失败
- **WHEN** 尚未验证的固定凭据未能完成令牌解锁或目标站点客户端证书握手
- **THEN** 系统不生成验证印章并显示不包含 PIN 内容的失败状态；只有令牌明确拒绝 PIN 时才删除该凭据，其他失败等待新的 USB 插入周期后再尝试

#### Scenario: 用户替换已保存 PIN
- **WHEN** 用户通过本机设置入口提交新的固定 PIN
- **THEN** 系统用新 PIN 替换当前用户原有凭据、清除旧验证印章，后续不再使用旧 PIN

#### Scenario: 用户删除已保存 PIN
- **WHEN** 用户请求删除已保存 PIN
- **THEN** 系统移除当前用户凭据并返回需要设置 PIN 的状态

#### Scenario: 诊断信息不泄露 PIN
- **WHEN** 设置、读取、解锁或认证过程成功或失败
- **THEN** 所有界面状态、日志和错误信息均不得包含 PIN 明文或可还原 PIN 的数据

### Requirement: 每个 USB 插入周期最多自动解锁一次
系统 MUST 在目标 USB Key 出现且存在受保护的固定 PIN 时，先尝试一次静默令牌解锁，再允许提交客户端证书。该 PIN 可以已有匹配验证印章，也可以处于首次/配置变化后的待验证状态。无论失败原因如何，同一插入周期内 MUST NOT 自动重试；明确的 PIN 拒绝还 MUST 删除该凭据并暂停后续周期的自动尝试，直到用户重新设置 PIN。

#### Scenario: 插入后静默解锁成功
- **WHEN** 目标 USB Key 新近插入、已保存 PIN 可用且令牌接受该 PIN
- **THEN** 系统在该插入周期只执行一次自动解锁，并进入等待目标客户端证书请求的状态

#### Scenario: 同一插入周期内不重复尝试
- **WHEN** 本插入周期已经执行过自动解锁
- **THEN** 后续设备事件、页面刷新、导航或证书请求均不得再次自动提交 PIN

#### Scenario: 明确的 PIN 拒绝暂停自动尝试
- **WHEN** 令牌明确拒绝已保存 PIN
- **THEN** 系统停止当前尝试、标记凭据需要重新设置，并在用户重新验证 PIN 前不因拔插或重启而再次自动提交该 PIN

#### Scenario: 非 PIN 原因失败允许新周期重试
- **WHEN** 自动解锁因设备拔出、提供程序暂不可用或其他未明确判定为 PIN 错误的原因失败
- **THEN** 系统停止当前周期的自动尝试，并仅在 USB Key 重新插入形成新周期后允许再次尝试

### Requirement: 客户端证书必须唯一且精确匹配
系统 MUST 只为已授权主机和端口，从浏览器提供的互信证书集合中自动选择唯一符合配置指纹及证书身份约束的客户端证书。系统 MUST 在令牌已成功解锁后才提交该证书。

#### Scenario: 唯一证书匹配并自动提交
- **WHEN** 已授权目标请求客户端证书、令牌已解锁，且互信证书集合中恰有一个证书同时匹配配置的指纹和身份约束
- **THEN** 系统自动选择该证书并继续 TLS 客户端认证

#### Scenario: 目标证书不存在
- **WHEN** 已授权目标请求客户端证书，但互信证书集合中不存在符合配置的证书
- **THEN** 系统不提交其他证书并显示证书缺失错误

#### Scenario: 匹配结果不唯一
- **WHEN** 已授权目标请求客户端证书，但匹配结果不是唯一一个证书
- **THEN** 系统不自动提交任何证书并显示证书匹配冲突

#### Scenario: 令牌未解锁时不提交证书
- **WHEN** 客户端证书请求到达时令牌解锁尚未成功或已经失败
- **THEN** 系统不自动提交证书，并显示当前认证阻塞原因

### Requirement: 启用自动认证前必须通过端到端兼容性验证
系统 MUST 在首次保存固定 PIN 或认证标识发生变化后，通过下一个符合条件的 USB 插入周期执行一次本机端到端验证，确认静默解锁状态能被浏览器的证书私钥操作复用。验证未成功前，系统 MUST NOT 将该配置标记为已验证，也不得在同一插入周期自动重试；但 MAY 使用受保护凭据完成这一次受限验证尝试。

#### Scenario: 兼容性验证成功
- **WHEN** 静默解锁完成，浏览器使用目标证书完成目标站点的客户端证书握手，且任何厂商 PIN 请求均由已授权的本机续接流程自动完成
- **THEN** 系统只写入与当前认证配置哈希绑定的非秘密验证印章，并在后续插入周期继续自动读取受保护凭据

#### Scenario: 提供程序状态不能被浏览器复用
- **WHEN** 静默解锁调用成功，但浏览器证书私钥操作仍要求再次输入 PIN，且未配置或无法安全启动受限的本机续接流程
- **THEN** 系统将该组合标记为不兼容、不生成验证印章，并显示需要安装或修复本机认证代理的错误

#### Scenario: 认证标识变化后重新验证
- **WHEN** 主机、端口、证书标识、提供程序名称或类型、密钥容器或密钥用途任一配置发生变化
- **THEN** 系统撤销原有已验证状态，并要求新的端到端兼容性验证

### Requirement: 厂商原生 PIN 窗口续接必须被严格授权和隔离
系统 MUST 优先使用令牌提供的受支持密码服务接口和浏览器客户端证书接口。只有配置显式启用本机续接、令牌已经接受本次 PIN、目标 USB 插入周期与目标 HTTPS 客户端证书请求仍有效，并且厂商进程映像、签名或文件哈希、Windows 会话、完整性级别、窗口标题、窗口类及必需子窗口结构全部精确匹配时，系统才可通过独立高权限代理向该厂商 PIN 窗口提交一次 PIN。对于由 WebView2 子进程创建且挂接在主应用窗口下的原生对话框，无论它是真正的子窗口还是由主窗口直接拥有的顶层模态窗口，代理 MUST 额外把候选根窗口或直接 owner 绑定到本次已经通过命名管道身份校验的精确主应用 PID，并精确匹配受签名子进程、根窗口指纹、对话框指纹、唯一密码输入控件和唯一默认确认按钮；不得枚举或接受其他应用实例下的同类窗口。代理 MUST 在读取健康检查或认证请求前验证命名管道调用方为安装时绑定的当前交互用户、会话、主应用最终绝对路径和应用代码 SHA-256，并 MUST 拒绝缺少调用方绑定的静态发布策略。每次认证 MUST 使用独立的不可预测随机标识，代理 MUST 拒绝已消费标识的精确重放。主应用及 WebView2 MUST 保持普通权限。PIN MUST NOT 进入命令行、剪贴板、普通文件、日志、状态文本或网页脚本。

#### Scenario: 精确匹配后续接厂商 PIN 窗口
- **WHEN** 已授权认证尝试正在等待客户端证书私钥操作，且唯一可见厂商 PIN 窗口满足全部配置指纹
- **THEN** 高权限代理把本次短生命周期 PIN 提交给该窗口一次并立即清除代理和 IPC 中的秘密缓冲区，随后由目标 TLS 结果判定是否生成验证印章

#### Scenario: TLS 成功先于代理执行完成
- **WHEN** 目标 TLS 成功事件在高权限代理完成厂商 PIN 窗口续接前到达
- **THEN** 系统等待本次代理结果，且只有代理提交成功与 TLS 成功同时成立才判定首次设置成功

#### Scenario: 非绑定主程序连接代理
- **WHEN** 同一用户会话中的其他进程连接代理，或主程序路径、主程序映像及任一绑定应用程序集哈希与已安装策略不一致
- **THEN** 代理在读取健康检查或 PIN 请求前关闭连接且不执行任何窗口输入

#### Scenario: 重放已消费的随机尝试标识
- **WHEN** 调用方再次发送代理已经消费的完整随机尝试标识
- **THEN** 代理拒绝该请求且不执行第二次窗口输入

#### Scenario: 窗口或进程指纹不匹配
- **WHEN** 候选窗口的进程映像、签名或哈希、Windows 会话、窗口标题、窗口类、子窗口结构任一不匹配，或同时出现多个匹配候选
- **THEN** 系统不得激活窗口或提交 PIN，并以可诊断但不含秘密的错误终止本周期

#### Scenario: 高权限代理不可用
- **WHEN** 本机代理未安装、版本或协议不匹配、权限不足、IPC 对端身份不匹配或在限定时间内未就绪
- **THEN** 系统不得降级为整个浏览器提权、剪贴板粘贴、坐标点击或未受约束的键盘输入，也不得在本周期自动重试 PIN

#### Scenario: 覆盖安装时旧代理延迟退出
- **WHEN** 计划任务已经报告停止，但旧代理进程仍在释放受保护目录中的可执行映像
- **THEN** 安装器必须等待计划任务停止且旧代理映像可写后才执行备份和覆盖；等待超时必须停止更新并执行安全回滚，不得并发覆盖或破坏回滚基线

#### Scenario: 输入前焦点或窗口状态变化
- **WHEN** 高权限代理准备输入后发现前台窗口、目标句柄、进程身份、可见性或启用状态发生变化
- **THEN** 系统在输入任何字符前中止本次续接并清除秘密缓冲区

#### Scenario: WebView2 子对话框精确匹配并续接
- **WHEN** 唯一密码子对话框位于本次受信主应用 PID 的窗口树中，且 WebView2 进程签名、根窗口、对话框、密码输入框和默认确认按钮全部符合配置
- **THEN** 代理激活受信根窗口、把焦点设到唯一密码输入框，在输入前重新验证全部身份，并只发送一次 PIN 与确认键

#### Scenario: WebView2 直接拥有的顶层模态密码框精确匹配并续接
- **WHEN** 唯一密码框是 WebView2 子进程创建的顶层模态对话框，其直接 owner 是本次受信主应用 PID 的精确根窗口，且进程签名、对话框、密码输入框和默认确认按钮全部符合配置
- **THEN** 代理允许 owner 根窗口处于模态禁用状态，激活该密码对话框本身、聚焦唯一密码输入框，并在输入前重新验证直接 owner 关系和全部身份后只发送一次 PIN 与确认键

#### Scenario: 密码框在代理武装后延迟出现
- **WHEN** 代理已经接受本次唯一请求，但 WebView2 尚未创建密码框
- **THEN** 代理只在配置的短超时内轮询严格窗口匹配，不激活任何非匹配窗口、不提交任何字符；唯一精确候选出现后才继续本次单次输入，超时或出现多个匹配候选时默认拒绝

#### Scenario: 相似子对话框不属于本次受信主应用
- **WHEN** 其他应用或另一个启动器实例出现相同类名和控件结构的 WebView2 子对话框
- **THEN** 代理拒绝该候选且不激活窗口、不聚焦控件、不提交 PIN

#### Scenario: 顶层密码框的 owner 不是受信根窗口
- **WHEN** 顶层 WebView2 密码框没有 owner、owner 不是受信主应用的精确根窗口，或 owner 关系在输入前发生变化
- **THEN** 代理拒绝该候选且不激活窗口、不聚焦控件、不提交 PIN

#### Scenario: 同一插入周期不重复续接
- **WHEN** 本插入周期已经向厂商 PIN 窗口提交过一次 PIN
- **THEN** 后续窗口事件、导航、刷新或超时均不得触发第二次提交

#### Scenario: 页面出现其他认证因子
- **WHEN** 页面要求验证码、动态口令、交易确认或其他每次变化的认证因子
- **THEN** 系统不自动读取、填写或确认该因子
