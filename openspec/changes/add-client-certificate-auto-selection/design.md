## Context

参见 [proposal.md](proposal.md) 的变更动机。现有程序已经按 Core、Windows、App 分层：Core 保存启动配置和协调状态，Windows 负责 USB 识别，App 封装 WebView2 并组合依赖。当前浏览器初始化后只导航到目标 URL，没有接管客户端证书请求，也没有秘密存储或令牌认证抽象。

最初目标设备使用传统 CryptoAPI CSP。实测旧证书私钥属于 `CCB HD CSP V3.0` 的 `SAMPLE_KEY_CONTAINER_1_RSA` 容器，提供程序类型为 RSA Full，KeySpec 为 `AT_KEYEXCHANGE`，私钥不可导出。原生“验证网银盾密码”窗口由 CSP 在浏览器访问私钥时创建，不属于网页 DOM。`CryptAcquireContext` 在 `CRYPT_SILENT` 下可取得指定容器，`CryptGetUserKey(AT_KEYEXCHANGE)` 也可取得密钥句柄，但仍需端到端证明通过 `PP_KEYEXCHANGE_PIN` 设置的状态能被 WebView2/Schannel 的后续私钥操作复用。

实机进一步确认，旧设备的标准 PKCS#11 `C_Login` 能验证 PIN，但该状态同样不能被 WebView2 使用的 CSP 复用。随后出现的窗口由 `C:\Program Files (x86)\CCBComponents\Detector\CCBDetector.exe` 创建：进程处于 High Integrity，主应用处于 Medium Integrity，Windows UIPI 会阻止主应用直接发送输入；窗口标题为 `E路护航网银安全组件`、类为 `#32770`，并包含 `Shell Embedding → Shell DocObject View → Internet Explorer_Server` 子窗口结构。厂商程序当前 Authenticode 签名有效，发布者为 `Shenzhen Excelsecu Data Technology Co.,Ltd.`，实测文件 SHA-256 为 `EDB0029E220ABCC32676B7AA90B2E012C4FB84AF0AD891BB0BA6B0F021FDB607`。

本次切换后的活动设备为 Tendyron 型号 `1780:0401`，总线描述 `Tendyron Token`，并以 CDFS 虚拟光驱暴露 `TENDYRON U-DISK USB Device`、卷标 `CCB`。当前插入实例的 RSA 客户端证书为 `GSB00000000002`，SHA-1 指纹 `2222222222222222222222222222222222222222`，CSP 为 `Tendyron OnKey CSP CCB v1.0`，容器为 `SAMPLE_KEY_CONTAINER_3`，KeySpec 为 `AT_KEYEXCHANGE`。显式无秘密硬件预检已确认 SetupAPI 能精确匹配该设备，并确认 `CRYPT_SILENT` 下可以打开此容器及取得用户公钥；该预检不读取凭据、不设置 PIN、不签名。完整 PIN 和目标 TLS 验收仍单独执行。

本设计受 [client-certificate-token-authentication 规格](specs/client-certificate-token-authentication/spec.md)约束。自动认证是便利功能，不改变 USB Key、证书私钥或站点本身的安全边界。

## Goals / Non-Goals

**Goals:**

- 让 Core 只负责认证状态机和策略，不依赖 Credential Manager、CryptoAPI 或 WebView2 类型。
- 把 PIN 的采集、保存、短暂使用和清除设计成独立生命周期，保证普通配置和诊断链路看不到秘密。
- 在导航前完成一次受限的令牌解锁尝试，并在 WebView2 客户端证书事件中做精确、唯一、默认拒绝的匹配。
- 先完成本机端到端兼容性探针；只有探针成功，才把当前认证配置视为可自动运行。
- 在标准接口状态无法跨进程复用时，通过权限隔离、精确匹配和一次提交的本机代理续接厂商 PIN 窗口，同时保持 WebView2 普通权限。
- 保留后续增加其他硬件令牌适配器或站点流程配置的空间，但不为尚未出现的提供程序建立通用插件系统。

**Non-Goals:**

- 不导出、复制或替换 USB Key 内的私钥，也不绕过令牌的 PIN 重试和锁定策略。
- 不操作未精确配置的原生窗口、厂商软键盘、验证码、动态口令、交易确认或站点登录后的业务页面。
- 不改变系统证书库、浏览器全局策略、USB Key 驱动或 CSP 安装。
- 不让后台服务、其他 Windows 用户或远程组件共享 PIN。

## Decisions

### 1. 用显式认证配置扩展现有启动配置

在现有启动配置中增加可选的 `ClientCertificateAuthentication` 段；未配置时保留现有“检测 USB 后打开页面”的行为，但不启用任何自动 PIN 或自动选证书能力。认证段包含：

- 稳定的配置 ID；
- 规范化后的目标 HTTPS 主机与端口；
- 证书 SHA-1 指纹、主题和颁发者约束；
- CSP 名称、提供程序类型、密钥容器及 `AT_KEYEXCHANGE` 或 `AT_SIGNATURE`；
- Windows 凭据目标名称，不包含秘密值。

加载时一次性校验 HTTPS、端口范围、指纹格式、非空标识和受支持的 KeySpec。主机比较使用解析后的规范主机名和有效端口，不用字符串前缀或后缀匹配。配置校验失败时不创建认证组件。

启动配置允许一个主 USB 匹配项和若干 `additionalUsbDevices` 白名单项；任一完整设备特征匹配都可启动页面。认证仍只有一份活动配置，USB 型号匹配不会放宽证书、CSP、容器或 KeySpec 的精确约束，也不会在多个证书中“选第一个”。当前配置保留旧 `1677:0054` 设备作为启动白名单，并把活动认证切换到 Tendyron `1780:0401` 的当前证书实例。未来若要让多个 Key 各自使用不同证书完成认证，应增加显式的“USB 身份 → 认证配置”映射，而不是根据枚举顺序猜测。

### 2. 用 Core 认证协调器管理一次插入周期

新增不依赖平台类型的认证协调器，并由现有 USB 启动协调流程调用。一次插入周期从目标设备由“未出现”变成“出现”开始，到设备移除结束。协调器维护至少以下阶段：

1. `需要设置 PIN`：没有凭据或验证印章无效；
2. `正在验证兼容性`：仅首次设置或认证标识变化时使用内存中的 PIN；
3. `正在解锁令牌`：本周期唯一一次 PIN 提交；
4. `等待客户端证书请求`：解锁会话存活且浏览器开始导航；
5. `正在完成客户端认证`：目标证书已交给 WebView2；
6. `就绪`、`不兼容` 或可分类的失败状态。

协调器以单调递增的插入周期 ID 记录 `Attempted`，从而屏蔽重复 WMI 事件、刷新和重复证书请求。只有一次真实的“移除后重新插入”才创建新周期。若平台明确报告 PIN 被拒绝，立即删除已保存凭据并进入“需要设置 PIN”，因此即使重启或重新插入也不会自动重复错误 PIN；其他瞬态错误只终止当前周期。

选择集中状态机而不是把判断分散在窗口事件、USB 回调和 WebView2 回调中，是为了让“最多一次”和“先解锁再选证书”可以用无硬件单元测试验证。

### 3. PIN 存入 Windows 当前用户凭据存储

Windows 适配层实现秘密存储接口，使用 CurrentUser 范围的 Windows Credential Manager 通用凭据。凭据目标由应用名和稳定配置 ID 组成；普通配置仅保存目标名称。另在用户本地应用状态中保存不含秘密的“认证配置规范化哈希 + 已验证”印章。哈希不匹配时不得自动读取或使用原凭据，必须重新进行兼容性验证。

首次设置使用 WPF 本机密码输入控件。PIN 从输入控件进入可清零的短生命周期缓冲区，经验证成功后直接写入 Credential Manager；失败时不持久化。读取后的托管和非托管缓冲区均在 `finally` 中尽力清零，异常、状态文本和日志只保留错误类别及允许公开的系统错误码。界面提供“重新设置”和“删除本机 PIN”，删除操作同时清除验证印章。

选择 Credential Manager 而不是 JSON、环境变量或自制加密文件，是因为它提供 Windows 用户隔离和成熟的凭据生命周期；选择 CurrentUser 而不是 LocalMachine，是为了避免同机其他用户或服务读取此凭据。DPAPI 文件可以达到类似加密强度，但会增加文件权限、格式和迁移管理，当前没有必要。

### 4. 用受支持的 CryptoAPI 路径解锁传统 CSP

Windows 令牌适配器通过窄封装的 P/Invoke 和安全句柄实现，固定执行以下受控流程：

1. 使用配置的容器、CSP 名称和提供程序类型调用 `CryptAcquireContext`，并设置 `CRYPT_SILENT`，确保调用自身不得弹出界面；
2. 根据配置的 KeySpec，通过 `CryptSetProvParam(PP_KEYEXCHANGE_PIN)` 或 `CryptSetProvParam(PP_SIGNATURE_PIN)` 提交短生命周期 PIN 缓冲区；
3. 取得对应的 `AT_KEYEXCHANGE` 或 `AT_SIGNATURE` 用户密钥，并对随机内存挑战执行一次最小私钥签名探针，以迫使 CSP 在进入浏览器前验证 PIN 和私钥可用性；
4. 返回一个可释放的解锁会话租约，在目标 TLS 握手完成、失败或超时前保持提供程序和密钥句柄存活；
5. 释放句柄并清零 PIN 及中间缓冲区。

微软文档分别定义了密钥交换和签名 PIN 参数；实现按精确 KeySpec 选择对应参数及用户密钥。签名探针只对随机内存数据操作，不导出私钥、不提交业务数据，也不替代最终的端到端握手验证。

错误映射分为：PIN 明确拒绝、设备不存在/移除、提供程序或容器不可用、不支持、未知错误。只有供应商返回值能够明确归类为 PIN 拒绝时才删除凭据；未知错误不得猜测为错误 PIN，也不得在同一周期重试。

不采用 CNG/NCrypt，是因为当前证书明确绑定传统 CSP；不调用厂商未公开签名和语义的私有 DLL 导出。原生窗口续接不作为通用兜底，仅在标准接口已验证但不能跨上下文复用、且后续第 9 节全部约束成立时启用。

### 5. WebView2 在导航前注册精确证书处理器

扩展现有浏览器抽象，使 App 可以在首次导航前注册客户端证书请求处理器，并把 WebView2 类型转换成 Core 可判断的请求快照。处理器执行以下同步判定：

- 请求是非代理的 HTTPS 请求；
- 规范主机和有效端口与认证配置完全相等；
- 当前插入周期已经取得有效解锁会话；
- WebView2 提供的互信证书集合中恰有一个证书同时匹配规范化指纹、主题和颁发者。

全部满足时设置该唯一证书并标记请求已处理。任一条件不满足时以“未选择证书”的已处理结果终止请求，阻止 WebView2 再弹默认选择器，并把分类错误交给认证协调器。非授权主机永远不能触发秘密读取或令牌解锁。

选择 WebView2 的客户端证书请求事件，而不是 Edge/Chromium 全局自动选证书策略，是因为事件只影响本应用实例、可以结合当前插入周期状态，并能按指纹默认拒绝。全局策略范围更大，而且不能解决 CSP PIN。

### 6. 固定本机凭据与兼容性验证印章分离

固定 PIN 通过独立的本机设置入口一次录入并立即写入当前 Windows 用户的 Credential Manager；替换凭据时先清除旧验证印章。正常启动不再弹出主程序 PIN 输入框，而是在目标 USB 出现后短暂读取该凭据。PIN 不进入源码、环境变量、启动参数、普通配置或日志。

Credential Manager 凭据和非秘密验证印章具有不同语义：凭据存在只表示用户已配置固定 PIN，匹配的验证印章才表示当前主机、证书、令牌及续接配置完成过端到端验证。显式保存固定 PIN 时同时写入与当前配置哈希绑定的非秘密“待验证”标记；普通的印章缺失、旧配置哈希或未知标记均不能授权读取 PIN。下一个符合条件的 USB 插入周期只有在正式印章或待验证标记精确匹配时才读取该受保护凭据并执行一次验证；只有目标 TLS 成功才把待验证标记替换为正式印章。窗口匹配、代理或握手失败都不生成正式印章，也不会在同一周期重试。令牌明确拒绝 PIN 时删除凭据和标记以避免持续消耗硬件重试次数，其他失败保留固定凭据和待验证标记供新插入周期再次验证。

正常流程固定为：目标 USB 出现 → 读取固定凭据一次 → 静默解锁一次 → 初始化浏览器处理器 → 导航 → 精确选择证书 → 完成握手 → 必要时写入验证印章。任何失败都会释放会话租约并停止本周期。

若用户在目标 USB 已插入且启动流程正等待固定凭据时完成保存，设置命令必须等待认证协调器完成新周期准备，再通过启动协调器现有的设备处理路径重新检查 USB、认证门和浏览器状态，并实际执行 WebView2 初始化与导航。该路径不得调用仅用于“外部流程已经完成导航”的状态通知，也不得在没有浏览器导航的情况下把空白宿主标记为“页面已就绪”；重复恢复请求仍由启动协调器的一次导航保护合并。

### 7. 测试分为无秘密自动测试和显式本机硬件验收

单元测试用假秘密存储、假令牌适配器和假浏览器事件覆盖状态机、一次尝试保护、错误分类、配置哈希失效、证书唯一匹配及非授权主机拒绝。Windows 适配器测试覆盖 Credential Manager 往返、删除、缓冲区清理和 CryptoAPI 参数映射，但测试凭据使用随机测试值，绝不包含真实 PIN。

真实硬件测试默认跳过，必须由开发者显式启动并在本机设置界面输入 PIN。它只使用正确 PIN 验证 `PP_KEYEXCHANGE_PIN`、私钥探针和 WebView2 握手复用；错误 PIN 和重试上限由假适配器测试，不对真实 USB Key 做破坏性试错。发布前还要扫描源码、配置、测试输出和发布目录，确认不存在 PIN 或测试秘密。

### 8. 实机失败后增加可配置的 PKCS#11 适配器

实机验收确认当前华大二代 Key 的 `CCB HD CSP V3.0` 在 `CryptSetProvParam(PP_KEYEXCHANGE_PIN)` 收到正确参数时仍返回失败，并把线程错误码保留为 `ERROR_SUCCESS`。这不能判定为密码错误，只能判定该驱动组合不支持当前标准 CryptoAPI 注入路径。

本机只读检查同时确认系统已经安装厂商提供的 64 位 `CCB_HDZB_2G_P11.dll`。该模块导出标准 PKCS#11 接口，并能在不提交 PIN 的情况下枚举到序列号为 `SAMPLE_KEY_CONTAINER_1` 的 `HDZB USBKey 2G`。因此认证配置增加可选的令牌解锁方式、绝对模块路径和精确令牌序列号；未配置时继续使用 CryptoAPI，当前设备配置改用 PKCS#11。

PKCS#11 适配器只调用公开标准接口：加载模块、初始化、枚举令牌、按精确序列号打开串行会话并执行一次 `C_Login`。成功后的会话保持到 TLS 验证结束、失败、超时或设备移除；释放时按所有权执行登出、关闭会话、结束模块并卸载。相同规范化模块路径的初始化、登录、会话存活和结束在进程内串行化，避免一个流程在另一个会话仍存活时结束模块。只有 `C_Login` 返回成功才能证明本次 PIN 已验证；“用户此前已登录”不会被当成本次输入成功，也不会触发凭据保存。PIN 使用短生命周期 UTF-8 字节缓冲区，调用返回后立即清零。模块加载失败没有原生返回码时保留空错误码，不再显示误导性的 `0x00000000`。

该适配器不会调用只有导出名而没有官方签名的 `T_VerifyPin` 等私有函数。首次设置仍必须通过目标 TLS 端到端探针；若浏览器要求厂商密码窗口，则转交第 9 节的受限代理，代理成功提交本次 PIN 且 TLS 成功后才允许保存。

### 9. 用独立高权限代理续接厂商 PIN 窗口

主程序新增与平台无关的原生认证续接契约，Windows 层负责 IPC 客户端，独立 `NativePromptBroker` 进程负责高权限窗口访问。代理安装到管理员保护的 `Program Files` 目录，并通过“当前交互用户、最高权限”的计划任务启动；安装和卸载各需要一次 UAC 确认。主应用和 WebView2 不提升权限，避免把远程网页内容放进高完整性进程。

安装代理时，安装器从发布目录解析主应用的最终绝对路径，并把主程序映像以及 `UsbWebLauncher.App`、`UsbWebLauncher.Core`、`UsbWebLauncher.Windows` 三个应用程序集的 SHA-256 写入管理员保护的已安装策略。代理在读取健康检查或认证请求前，先根据命名管道客户端 PID 验证当前交互用户 SID、会话、主程序最终路径和全部绑定哈希；发布目录中的静态策略不能直接启动代理。主应用升级导致任一哈希变化时必须重新安装代理策略。覆盖安装先停止旧任务，并等待计划任务进入停止状态且旧代理映像已经释放，再在受保护目录内备份旧代理与策略；未释放时不得覆盖。替换或重启任一步失败时恢复并重启旧版本；任务启动请求成功后仍保留原备份，直到新代理与绑定主应用完成一次身份验证通过的健康握手才由新代理清理。若新代理未能健康启动，后续安装复用原备份，不把故障版本覆盖为回滚基线。

主应用为每次认证生成独立的 128 位密码学随机尝试 ID，只在令牌已经接受 PIN、WebView2 已选择精确证书且目标 TLS 仍在限定时间内等待时，通过仅限当前用户的本机命名管道发送请求。代理按完整随机 ID 记录有限数量的已消费请求并拒绝精确重放；进程重启不会复用可预测的插入周期序号。管道协议固定版本、长度上限和超时，不把 PIN 放入命令行；双方验证会话 ID、对端进程身份、代理版本和一次性尝试 ID。PIN 以长度前缀缓冲区传输，读取、发送和接收完成后均在 `finally` 中清零。若目标 TLS 成功事件先于代理执行结果到达，首次设置流程等待代理完成；只有代理提交成功且 TLS 成功才判定设置成功。

代理支持两种显式配置的窗口作用域。传统厂商进程模式逐项验证唯一顶层窗口：当前交互会话、High Integrity、精确进程绝对路径、有效 Authenticode 发布者和/或精确文件 SHA-256、窗口标题、窗口类及子窗口类链。WebView2 对话框模式只枚举本次已经通过命名管道身份校验的主应用 PID 所拥有的顶层窗口及其真正后代，同时枚举直接 owner 为该精确主应用根窗口的 WebView2 顶层模态对话框，并要求根窗口标题和类前缀、子进程文件名、有效 Authenticode 发布者、会话、完整性级别、空或非空窗口标题、窗口类、唯一密码输入控件和唯一默认确认按钮全部匹配。顶层模态对话框出现时，owner 根窗口因模态关系被禁用是预期状态，但直接 owner 关系必须保持不变。WebView2 Evergreen 的版本目录和文件哈希会变化，因此该模式不绑定版本化绝对路径，而以精确主应用实例、`msedgewebview2.exe` 文件名和 Microsoft 签名共同限定目标。

代理武装发生在 WebView2 提交证书之前，因此密码框可能稍后才创建。代理在配置的短超时内只轮询严格匹配；零匹配时等待，多个匹配时立即拒绝，期间不激活窗口也不输入。唯一候选出现后，真正的子对话框路径激活受信主应用根窗口；直接拥有的顶层模态对话框路径激活密码对话框本身。代理随后临时附加目标窗口线程的输入队列并把焦点设置到精确匹配的密码输入控件。输入前必须重新采集并比较根窗口或直接 owner、对话框、进程身份和两个控件句柄，同时再次确认对应前台窗口和密码输入框焦点；随后才把每个字符映射为当前键盘布局下不需要 Ctrl/Alt 的虚拟键，按需要生成成对的 Shift 与字符按下/释放事件，并在同一次 `SendInput` 批次末尾发送确认键。安全控件会过滤 `KEYEVENTF_UNICODE`，因此不得使用 Unicode 包或对不可映射字符降级输入。任何属性变化、多个候选、焦点抢占、不可映射字符、部分输入报告、超时或协议错误都立即停止，返回分类结果且不重试。

考虑过两种替代方案：其一是把整个 WPF/WebView2 应用声明为管理员权限，虽然实现简单，但会让远程网页渲染进程处于高权限，风险不可接受；其二是调用 `T_VerifyPin` 等未公开厂商导出，无法证明 ABI、语义和重试行为，继续否决。高权限代理增加一次安装成本，但把特权和窗口输入限制在最小进程、最短时间及精确目标上。

## Risks / Trade-offs

- [厂商 CSP 的 PIN 缓存可能只绑定调用上下文，WebView2/Schannel 无法复用] → 首次设置必须通过真实端到端探针；失败即标记不兼容，不提供界面注入兜底。
- [PKCS#11 登录会话不能被 WebView2/Schannel 的 CSP 私钥上下文复用] → 保持会话到 TLS 终止，并仅在精确授权的高权限代理可用时续接厂商 PIN 窗口；仍不回退到私有函数。
- [高权限输入可能因错误窗口或焦点竞争泄露 PIN] → 同时校验进程路径、签名/哈希、会话、完整性级别、窗口类/标题/子窗口链和唯一性；激活后、输入前再次校验前台句柄，任一变化默认拒绝。
- [高权限代理本身扩大攻击面] → 代理安装在管理员保护目录、协议限长、管道限当前用户、安装策略绑定主程序路径及应用代码哈希、先验证调用进程再读取请求、只接受固定动作、不承载网页、不读写任意文件，并支持显式卸载和版本失配拒绝。
- [一次私钥签名探针仍会调用硬件私钥] → 仅签随机内存挑战、不保存签名、不发送业务数据，并计入本插入周期唯一一次认证尝试。
- [错误 PIN 会消耗硬件重试次数] → 同一周期最多一次；明确拒绝后立即删除凭据并要求重新设置；真实硬件测试禁止故意使用错误 PIN。
- [供应商错误码可能含义不稳定] → 默认归类为未知且不重试，只有经过实机确认的明确错误码才映射为 PIN 拒绝。
- [证书续期会改变指纹] → 默认拒绝并要求更新配置、重新验证；不自动放宽到同主题任意证书。
- [Credential Manager 保护的是 Windows 用户边界，不防御已控制当前用户会话的恶意程序] → 不扩大到机器级存储，不在内存中长期保留 PIN，并维持 USB Key 这一独立硬件因素。
- [握手成功判定依赖目标站点导航行为] → 只允许预先配置的成功 URL/导航条件，并设置超时；模糊结果不得生成验证印章。

## Migration Plan

1. 先发布包含可选认证配置、设置界面和禁用状态的版本；旧配置缺少认证段时继续原有启动流程，不自动使用 PIN。
2. 为当前目标补充主机、证书、CSP、提供程序类型、容器及 KeySpec 标识，但保持自动认证未验证。
3. 用户通过一次 UAC 确认把高权限代理安装到管理员保护目录并注册当前用户最高权限计划任务；主程序验证代理版本和健康状态。
4. 用户通过独立本机设置入口一次录入固定 PIN 到 Credential Manager；真实 USB Key 出现后应用自动读取一次，标准解锁后由代理用虚拟键自动续接厂商窗口，TLS 成功后生成配置验证印章。
5. 验证“启动时已插入”和“运行后插入”两条路径均只发生一次自动解锁和最多一次厂商窗口续接，且不出现证书选择器或需要人工输入的 PIN 窗口。
6. 以自包含 win-x64 包覆盖发布目录前保留上一版本副本，并确认发布物不含秘密。

回滚时先通过代理卸载入口删除计划任务和 `Program Files` 中的代理文件，再恢复上一版本程序和配置。新版本写入的 Credential Manager 条目及非秘密验证印章可通过新版本的“删除本机 PIN”入口清除；若程序已经回滚，则使用 Windows 凭据管理界面删除对应的 `UsbWebLauncher` 通用凭据。回滚不修改证书、驱动或 USB Key。
