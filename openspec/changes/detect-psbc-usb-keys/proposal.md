## Why

当前应用已经具备建设银行 USB Key 流程和银行选择入口，但邮储银行仍是未配置分支。邮储 Key 覆盖多个厂商，需要参照“邮储银行网银助手”的厂商插件式识别方式建立独立检测能力，同时保证只有用户当前选择的银行流程能够运行。

## What Changes

- 增加邮储银行 USB Key 检测能力，覆盖飞天、华大智宝、天地融、深圳文鼎创和握奇五个厂商族。
- 将邮储检测拆分为物理设备发现、厂商识别、驱动/服务/CSP 环境检查和 Token 身份探测，区分未插入、已插入但环境不可用、可用三类结果。
- 允许同一个物理 Key 同时满足建设银行和邮储银行的识别条件；设备匹配不承担唯一银行归属判断。
- 以用户当前选择的银行作为唯一业务路由：只创建、监听和运行该银行的检测、认证、网页和业务运行时。
- 银行切换时撤销并释放旧银行运行时，忽略旧监听器的延迟回调，防止未选中银行触发认证或业务。
- 普通插入检测不调用可能改变设备状态的初始化接口，例如 `TokenInitialize`。
- 基础实现不复制或打包邮储助手的专有 DLL；如后续必须直接调用其 x86 厂商接口，将作为独立 broker 方案另行确认。

## Capabilities

### New Capabilities

- `psbc-usb-key-detection`: 邮储五厂商 USB Key 的发现、厂商探测、环境状态、Token 身份和插拔生命周期要求。
- `ccb-usbstor-key-detection`: 明确建设银行检测结果不代表设备的排他银行归属，并约束其只在建设银行被选中时驱动业务流程。

### Modified Capabilities

无。

## Impact

- Core 设备描述、检测策略、匹配结果模型和配置验证。
- Windows USB 设备枚举、同一物理设备关联、服务/CSP/注册表环境探测和元数据重试。
- App 银行流程组合、监听器生命周期、运行时切换和陈旧回调隔离。
- 邮储五厂商样本夹具、重叠匹配、银行切换、缺失驱动/服务及插拔回归测试。
- 主程序继续保持 x64；本次基础范围不直接加载邮储助手的 x86 DLL。
