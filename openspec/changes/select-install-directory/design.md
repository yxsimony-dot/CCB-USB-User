## Context

安装器当前使用 DisableDirPage=yes、UsePreviousAppDir=no，Invoke-Install.ps1 另有固定路径校验。事务和认证组件多数接口已经接收真实 AppDirectory。直接开启目录页仍会在安装阶段失败。

## Goals / Non-Goals

首次安装可在确认前选择目录；升级继续识别该位置并刷新认证绑定。用户数据独立保留。此次不做已安装程序的在线搬迁、不改变认证组件目录、不改变更新包缓存下载行为。

## Decisions

目录页始终显示。首次默认 LocalAppData/Programs/UsbWebLauncher，选择可写本地固定磁盘子目录；升级读取稳定 AppId 的 HKCU InstallLocation，原地升级不迁移，界面明确说明如何卸载后搬迁。兼容旧默认位置的产品记录和未完成事务。

验证早于载荷安装、依赖安装和认证组件变更；安装事务入口再次校验。检查路径是绝对本地路径、不处于驱动器根/系统及用户数据目录、无重解析跳转或脚本解析歧义，保留现有文件所有权检查及恢复逻辑。普通用户权限安装，认证组件按既有流程单独请求授权。

更新窗口不再把自定义目录误标为开发目录，也不承诺固定目标路径；提示以安装向导中的选择或现有登记为准。

## Risks / Trade-offs

- 不允许升级中换目录：单个认证组件只绑定一个应用位置，迁移还涉及旧卸载登记和恢复，用户可通过正常卸载后重新选择完成。
- 任意路径扩大误操作范围：在确认和事务两个边界校验路径，保留个人文件和失败恢复测试。
- 实机安装会注册认证组件：本次自动验证和向导预览不执行真实安装，不声称完整 UAC/升级验收已完成。

## Validation

使用临时合成目录测试中文空格路径、注册位置复用、路径拒绝、升级恢复和外部文件保留；执行完整 .NET、浏览器和包装测试，编译真实安装包并检查版本及清单。若能安全打开向导则只预览目录页并取消，不执行安装。main 推送按既有自动发布流程生成正式安装包。
