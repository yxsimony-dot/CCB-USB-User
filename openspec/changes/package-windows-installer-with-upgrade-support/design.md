## Context

动机与能力边界见 `proposal.md`。当前 App 为 WPF/.NET 8、win-x64，正式目录含自包含运行库、WebView2 Loader、浏览器扩展及单文件自包含 broker；不能直接将现用发布目录作为安装载荷，因为其中仍存在旧 `UsbWebLauncher.App.exe.WebView2` 缓存。`WpfWebView2Control` 使用 `browserExecutableFolder: null`，依赖目标机 WebView2 Runtime；建行扩展通过 `ccb.detector.ukey.edgeextension` 连接目标机安装的官方原生组件。

PIN 位于当前用户 Windows Credential Manager；下载目录设置在 `%LOCALAPPDATA%\UsbWebLauncher\download-settings.json`，浏览器会话在同一用户数据根目录的 `browser-sessions` 下。Broker 安装在 Program Files，使用全机固定任务名和管道名，任务绑定当前交互用户；安装时计算主 exe 和 App/Core/Windows 三个 DLL 的路径与 SHA-256。现有安装器只回滚自身二进制和策略，尚不提供 App 整包回滚。当前 `--install` 退出成功也不等于新版主程序已完成健康握手。

## Goals / Non-Goals

**Goals:**

- 使用一个安装 EXE，在有网络、可进行同账号管理员确认的 Windows x64 交互桌面上完成应用安装和可见的环境初始化。
- 固定产品标识、应用目录与版本来源，使以后安装新版是覆盖升级；保留 PIN、下载目录和已完成 PDF。
- 将安装、依赖就绪、broker 绑定及健康验证分别建模；失败有可理解的状态与恢复入口。
- 从仓库干净检出构建，产物可追溯到版本和 Git commit，不依赖开发机已有 publish 文件。

**Non-Goals:**

- 不发布 ZIP、自动更新器、自动 GitHub Release、后台版本检测或 Git 凭据管理。
- 不承诺所有 Windows 版本、32 位系统、原生 ARM64、SYSTEM 静默安装、多用户并行或跨账号提权可用。
- 不迁移其他电脑的 PIN、证书、浏览器登录状态；不重新实现银行驱动或复制本机驱动安装目录。
- 不修改网银业务、Key 识别、PIN 大小写输入和导出规则；不以安装成功代替真实银行登录/下载验收。

## Decisions

### 1. 单一安装程序与当前用户应用目录

采用固定版本的 Inno Setup 6 生成安装 EXE，安装器正常以交互用户运行；仅官方前置程序及自有 broker 安装调用单独请求 UAC。应用固定安装到 `%LOCALAPPDATA%\Programs\UsbWebLauncher`，开始菜单和卸载注册按当前用户创建，主程序保持普通完整性级别。第一版创建固定 installer AppId GUID 并纳入源码，之后版本不得再生成新 GUID。产品机器标识固定为 `usb-web-launcher`，版本不参与目录和 AppId。

选择 per-user 是为了让安装目录、快捷方式、PIN 和设置属于同一发起用户，避免提升后误落入另一管理员的用户目录。备选全机主程序安装会同时涉及多用户使用承诺及管理员用户配置隔离，本期不采用；不提供可任意移动的便携目录。安装器应阻止直接以另一用户/提升会话启动造成用户归属不明，提示返回目标交互用户正常运行。

### 2. 单电脑单业务用户及权限边界

App 的 per-user 安装不意味着 broker 是 per-user：保留现有 `%ProgramFiles%\UsbWebLauncher\NativePromptBroker`、任务名及管道协议，明确一期一个电脑仅支持一个指定交互 Windows 用户。本机受保护安装记录保存 owner SID、产品标识和最终应用路径；安装、升级、修复、卸载都核对所有权。检测到另一用户已占用时停止 broker 变更并说明需原用户卸载/迁移，不能无提示抢占任务或删除其组件。

提升前保存发起用户/会话身份，提升端仍核对当前交互会话身份。支持边界为同一交互管理员用户通过 UAC；标准用户提供另一管理员账号、SYSTEM、无交互会话或无法证明原用户时不得伪装成功，不改变其他用户凭据/任务。现有 WTS 用户解析可复用，但必须通过测试验证，不能仅凭使用了 `runas` 宣称跨账号支持。主程序首次启动与 PIN 设置必须回到原交互用户非提升进程。多用户 broker 和以不同管理员长期运行 broker 另开变更。

### 3. 干净载荷与官方前置依赖

从新的 staging 目录 publish App 与 broker，载荷白名单为运行文件、通用 profile、完整建行扩展、未绑定的 broker 策略及安装资源。不递归复制现用发布目录。阻止纳入缓存、日志、凭据、证书、PDF、测试数据、调试端口参数、备份或开发机绝对路径。新生成的快捷方式指向最终安装路径，不复制旧 `.lnk`。

首次初始化按状态展示 WebView2 Runtime、银行原生 host/驱动、自有 broker、PIN。`.NET` 随应用自包含，无需目标机 SDK。WebView2 使用 Evergreen Runtime：存在且能完成所需扩展 API 初始化则复用，否则从经核实的 Microsoft 官方来源下载/运行安装器。银行依赖使用经核实的建行官方安装入口/安装器并复用其用户界面；不能只以 USBSTOR 存在作为认证环境已安装的证据，至少核对官方 native host 注册及目标文件可用，并在应用初始化时验证通信能力。

依赖目录清单在源码记录官方来源、检测方法、预期签名发布者/校验方式、退出码与重启语义；具体 URL 和兼容版本在实施时向官方核实并记录，不从历史日志或非官方镜像取得。不能验证来源/签名、网络失败、用户取消或安装器要求重启时显示未就绪及可恢复的操作。不能安全自动启动银行安装器时打开官方安装入口，等待用户完成后重新检测，明确此时尚未可用。第三方组件不跟随本应用卸载或失败回滚被删除。

只承诺 Windows 10 2004/build 19041 及以上 x64 中通过验收的 Windows 版本；不得将框架目标版本当作全版本验收。最低系统与依赖版本写入发布清单；Windows 11 x64 以及仍满足官方运行库要求的 Windows 10 x64 至少各有一项干净机验收。

### 4. 用户数据与卸载

沿用 credential target 的 namespace/authentication ID、现有用户数据目录，不把 PIN 写进配置或安装参数。新电脑首次输入 PIN，同机同用户覆盖安装直接保留。默认下载目录仍为当前用户桌面；有效已保存目录保持不变，目录不可用时提示重新选择，不偷偷改成安装目录。

普通卸载默认删除应用及本产品拥有的 broker/任务，保留 PIN、下载目录设置和 PDF。如提供“清理本机配置”选项，必须明确单独勾选，仅删除该用户本产品凭据和设置；永不递归清空下载目录。升级内部清理旧载荷不得调用普通卸载的 broker 删除或用户数据清理逻辑。

### 5. 覆盖升级、绑定与回滚

只支持同用户同 AppId 的同版本修复或更高稳定版本升级；默认拒绝降级，避免新设置无法被旧版理解。所有权与兼容性检查在改变旧安装之前完成。保留旧应用完整清单、版本、broker 二进制/策略及任务身份元数据，使用仅包含技术元数据的安装事务记录；不备份 PIN 或业务 PDF。

正常升级顺序：

1. 检查磁盘/目录、所有者和依赖，正常通知本应用中止业务并退出，确认其文件已释放；不终止其他银行程序。
2. 在安装目录旁暂存并验证完整新版本，备份受控旧载荷和安装元数据，再替换最终应用文件。
3. 由最终目录包重新安装 broker，更新 exe＋三个 DLL 的哈希及当前 owner SID；保留旧组件备份。
4. 以原用户普通权限启动最小健康检查，验证新主程序能连接绑定后的 broker，版本/协议相符；健康检查不启动银行业务、不读出 PIN。
5. 只有安装文件、broker 和健康检查都成功，才提交新版本和卸载注册、清理备份并显示升级完成。

替换、安装或健康检查失败时恢复旧应用载荷/版本、旧 broker/策略和原任务身份，再验证旧版健康；恢复失败保留备份和事务状态，清楚报告需要修复，禁止自动启动半更新业务。现有 broker 备份逻辑须与外层安装事务协调，不能在 App 新版本尚未验收前删去唯一可用备份。第三方依赖安装在事务外，只报告其结果，不尝试卸载回滚共享依赖。

本期对已捕获失败提供完整恢复，并使中断事务可在下次运行安装器时识别并选择恢复/修复；不承诺断电瞬间无损原子替换或全自动后台恢复。固定目录支持未来更新程序复用同一个安装 EXE，无需另造在线更新替换协议。

### 6. 统一版本、可重复构建与 GitHub 契约

`build/version.json` 作为唯一产品版本源，包含稳定 productId、一次性 installer AppId、SemVer 产品版本和发布通道；构建派生 Windows 四段文件版本、App/Broker InformationalVersion 和安装器版本，Git commit 作为构建元数据。Git tag 若存在必须与声明版本匹配，不能从本地当前日期或任意旧 exe 推导发行版版本。

固定 SDK、NuGet 依赖锁文件与打包工具版本，提供一个已文档化的 PowerShell 构建入口：检查工具 → locked restore → 测试 → 全新 staging 自包含 publish → 载荷检查 → installer 编译 → 生成校验/发布清单。缺工具、依赖锁不一致、测试失败、敏感文件混入或版本不一致即失败。这里“可重复”指干净检出可以生成同一功能/版本的可安装包；签名和时间戳可能改变字节，不宣称带签名包比特级重现。

仓库确定为 `https://github.com/yxsimony-dot/CCB-USB-User`。本期本地输出 `UsbWebLauncher-<version>-win-x64-setup.exe`、`SHA256SUMS`、`release-manifest.json`；这两个元数据文件是安装包附属物，不是便携 ZIP。清单 schema v1 至少包含 productId、version、channel、platform、architecture、minimumOsVersion、sourceRepository、sourceCommit、installerFileName、size、sha256、brokerProtocolVersion、settingsSchemaVersion。可选 releaseNotesUrl/downloadUrl 在未来正式发布时填写，不生成指向不存在 Release 的 URL，不含 token。

未来 GitHub Releases 下载发现可消费该接口，并继续运行相同安装器完成事务。当前不创建 GitHub Release、不上传二进制、不检查远程版本、不持久化 GitHub 凭据。SHA-256 只校验传输/文件一致性，不等于发行者身份；若没有可用代码签名证书，保留签名接入点并明确包未签名，不能伪称已消除 SmartScreen 提示。

## Risks / Trade-offs

- [官方依赖安装参数、签名或下载地址变化] → 实施时核实官方来源，记录版本和探测方法；失败展示未就绪，保留官方安装入口。
- [per-user App 与全机单用户 broker 不对称] → 提前检查 owner SID；拒绝跨用户覆盖，本期不提供多人并行使用承诺。
- [覆盖升级时文件仍被占用] → 先请求正常退出并等待有限期限；超时提示关闭，不杀其他程序、不继续半套替换。
- [broker 更新成功但主程序绑定不健康] → 以新主程序健康检查作为提交条件；失败恢复整包，不只恢复 broker。
- [旧开发入口仍能启动另一版本] → 首装从最终安装目录重新绑定，新快捷方式只指向该目录；旧目录不自动删除，不导入其缓存，旧绑定失效给出说明。
- [无代码签名导致系统提示] → 如实标记签名状态，保留官方依赖独立签名验证和安装包 hash；不在产品里宣称“任何电脑免提示”。

## Migration Plan

先完成自动化构建/载荷/安装事务测试，再在干净 Windows x64 做首装；随后以同一用户执行 N→N+1、同版本修复、失败恢复、降级拒绝、卸载保留数据验收。现有开发机已有 PIN 与下载目录保持在原位置，只将主程序装到固定路径并重绑 broker。验证版本显示、Key 空闲检测、启动/中止/拔 Key 退出、PIN 自动输入、弹窗处理及流水/回单命名的回归结果；真实银行操作仅按已授权范围执行，不为打包测试自动提交额外业务。

交付安装 EXE 和附属校验/发布清单，附首装、升级、修复和卸载说明及实际已验证系统列表。部署 Git 源码与创建本提案不代表安装包已构建或已发布。
